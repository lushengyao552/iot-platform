# 需求变更题库（共享）

> 用户做完基础功能后，随机插入需求变更。训练工程应变，不是背 CRUD。

## 早期变更（stage05-08 插入）

1. **需求变更 1**：产品说"图书名要支持繁体/简体搜索"，你现在的 like 怎么改？
2. **需求变更 2**：管理员说"分类排序 sort 字段不够，要支持拖拽"，接口怎么设计？
3. **需求变更 3**：用户说"注册时昵称可以不填，默认用用户名"，改哪里？
4. **需求变更 4**：产品要求"所有接口返回时间统一用毫秒时间戳"，怎么全局改？

## 中期变更（stage10-12 插入）

5. **需求变更 5**：产品要求"一个用户最多借 5 本书"。
   - 你现在的代码要改哪几处？
   - 已借超过 5 本的老用户怎么办？
6. **需求变更 6**：产品又改了，"管理员可以在后台调最大借阅数量"。
   - 这个 N 要存哪？
   - 已借超过新 N 的用户怎么处理？
7. **需求变更 7**：财务说"逾期每天罚款 0.5 元"。
   - 罚款金额什么时候算？
   - 还书时怎么收？
   - 不交罚款能不能借新书？
8. **需求变更 8**：产品说"续借功能：用户可以续借一次，应还时间延长 15 天"。
   - 数据库要加字段吗？
   - 已逾期的书能续吗？
9. **需求变更 9**：安全要求"密码每 90 天必须改"。
   - 怎么记录上次改密时间？
   - 改密后旧 token 怎么办？

## 后期变更（stage13-16 插入）

10. **需求变更 10**：图书详情接口要支持"点赞数"，点赞要实时。
    - 点赞存哪？DB 还是 Redis？
    - 高并发点赞怎么扛？
11. **需求变更 11**：运营要"热门图书榜"，每小时更新一次。
    - Redis ZSet 怎么搞？
    - 什么时候算"热门"？
12. **需求变更 12**：用户反馈"借书成功后邮件通知太慢"。
    - 现在是同步还是异步？
    - 怎么改？
13. **需求变更 13**：数据库要分库分表了（假设数据量涨到千万级）。
    - 哪些表先动？
    - 现在的设计要改什么？
14. **需求变更 14**：要支持多校区图书馆。
    - 书要带校区吗？
    - 用户借书只能在本校区吗？
15. **需求变更 15**：要支持预约借书：书借完了，用户能预约，还回时通知。
    - 新增什么表？
    - 还书时怎么知道通知谁？
    - 预约队列怎么排？

## 终极变更（stage18 前练手）

16. **需求变更 16**：老板说"我们要做 SaaS，多租户"。
    - 每张表加 tenant_id？
    - 怎么让用户只看到自己租户的数据？
17. **需求变更 17**：要开放 API 给第三方系统。
    - 鉴权方式怎么改？
    - 限流怎么做？
18. **需求变更 18**：要接微信小程序登录。
    - 用户体系怎么合并？
    - 已有账号怎么绑定？

## 出题节奏

- 用户刚把一个模块做完，趁热打铁给一个相关变更
- 不要一次抛五个变更
- 让他自己说"要改哪几处"，再说"为什么"
- 改完问他："这次改动你最担心出什么问题？"
