## 二、项目技术栈地图

这是本项目真实的技术栈（不是泛泛的 Spring Boot 教程），一图看懂请求是怎么走的、中间件在哪里：

```
┌─────────────────────────────────────────────────────────────┐
│                        浏览器 (React 前端)                    │
│   React 18 + TypeScript + Vite + Ant Design + Axios + Zustand│
│   端口 5173（开发），通过 Vite 代理把 /api 转发到 8080        │
└──────────────────────────┬──────────────────────────────────┘
                           │ HTTP 请求（JSON，Authorization: Bearer <token>）
                           ▼
┌─────────────────────────────────────────────────────────────┐
│                  Spring Boot 主应用（端口 8080）              │
│        context-path = /api（所有接口都带 /api 前缀）          │
│                                                              │
│  JwtInterceptor（拦截器） ── 校验 Token，存入 UserContext     │
│          ▼                                                   │
│  Controller（@RestController）── 接收请求、参数校验、权限判断  │
│          ▼                                                   │
│  Service（@Service + @Transactional）── 业务逻辑、事务、DTO↔VO │
│          ▼                                                   │
│  Mapper（MyBatis-Plus BaseMapper）── 数据访问、自定义 SQL      │
│          ▼                                                   │
└──────────┬──────────────────────┬──────────────────┬─────────┘
           │ SQL                  │ 缓存/锁          │ 异步消息
           ▼                      ▼                  ▼
   ┌───────────────┐      ┌───────────────┐   ┌─────────────────┐
   │  MySQL 8.0    │      │   Redis 7     │   │   RabbitMQ 3.12 │
   │  (3306)       │      │   (6379)      │   │  (5672/15672)   │
   │  4 张表       │      │ 图书详情缓存    │   │ 异步通知+延迟提醒 │
   └───────────────┘      │ 借阅分布式锁    │   └────────┬────────┘
                          └───────────────┘            │ 消费消息
                                                       ▼
                                          ┌──────────────────────┐
                                          │ notification-service  │
                                          │ （通知微服务，8081）   │
                                          │ 独立部署、幂等消费      │
                                          └──────────────────────┘
```

**一句话总结技术栈分工**：
- **React** = 界面（发请求、展示数据）
- **Spring Boot** = 大脑（接请求、跑业务）
- **MyBatis-Plus** = 翻译官（把 Java 对象和 SQL 互相转换）
- **MySQL** = 账本（持久化存数据）
- **Redis** = 快速缓存 + 分布式锁（缓解 MySQL 压力、防并发超卖）
- **RabbitMQ** = 邮局（异步解耦、延迟消息）

## 四、项目代码 ABC 分类（哪些值得学、哪些别浪费时间）

> 不要平均用力读所有代码。按「对吃透项目、对面试、对成长」的价值分三档：

### A 类：必须彻底搞懂（逐行看懂 + 能复述 + 能改）

| 代码 | 为什么是 A 类 |
|------|--------------|
| `application.yml` | 理解项目怎么连 MySQL/Redis/RabbitMQ、context-path、逻辑删除配置 |
| `schema.sql` | 4 张表的设计是理解一切业务的基础 |
| `LibraryApplication.java` | 理解 `@SpringBootApplication`、`@MapperScan` |
| `common/result/Result.java` + `ResultCode.java` | 统一返回格式，前后端契约 |
| `common/exception/BusinessException.java` + `GlobalExceptionHandler.java` | 异常体系，企业项目标配 |
| `controller/` 全部 5 个 | RESTful 设计、参数绑定、权限判断 |
| `service/` + `service/impl/` 核心实现 | 业务逻辑 + 事务 + DTO↔VO 转换 |
| `mapper/` 4 个 | BaseMapper + 自定义 SQL + 原子扣库存 |
| `entity/` 4 个 | `@TableName/@TableId/@TableLogic` 注解 |
| `interceptor/JwtInterceptor.java` | 认证流程核心 |
| `util/JwtUtil.java` | JWT 生成与解析 |
| `util/UserContext.java` | ThreadLocal 请求上下文 |
| `util/RedisService.java` | 缓存 + 分布式锁封装 |
| `util/MessageProducer.java` | 消息发送 + 可靠性 |
| `dto/` + `vo/` | 三层对象分离（第 7 课重点） |

### B 类：理解原理即可（知道它是干嘛的、为什么这么配，不必逐行背）

| 代码 | 为什么是 B 类 |
|------|--------------|
| `common/config/RedisConfig.java` | 理解序列化配置的原因（JSON vs JDK 二进制）即可 |
| `common/config/RabbitMQConfig.java` | 理解交换机/队列/绑定/死信的概念即可 |
| `common/config/MyBatisPlusConfig.java` | 理解分页插件 + 乐观锁插件注册即可 |
| `common/config/WebMvcConfig.java` | 理解拦截器注册 + CORS 跨域即可 |
| `common/config/MyMetaObjectHandler.java` | 理解自动填充 createTime/updateTime 即可 |
| `service/impl/MessageConsumer.java` | 理解 `@RabbitListener` + 手动 ACK 即可 |

### C 类：现在直接用，不必深挖

| 代码 | 为什么是 C 类（别浪费时间） |
|------|---------------------------|
| Lombok 注解的底层实现（`@Data` 怎么生成字节码） | 会用即可，初学阶段别钻注解处理器 |
| Knife4j/Swagger 的 `@Tag/@Operation/@Schema` 细节 | 会写接口文档即可，别纠结 OpenAPI 规范 |
| `LibraryApplication.java` 里的 `System.out.println` 启动横幅 | 纯打印，无技术含量 |
| Hutool 库的全部 API | 用到再查，不用背 |
| `target/`、`node_modules/`、`.gradle/` 等生成目录 | 构建产物/依赖缓存，别读 |
| notification-service 里 `NotificationService` 的内存存储 | 演示用，知道「实际要接数据库」即可 |

> **一句话**：把 80% 精力放在 A 类，B 类理解原理，C 类扫一眼就过。

## 六、项目文件学习顺序（先看哪个、后看哪个、哪些先别碰）

### 第 1 步：先看「说明 + 配置」（建立全局观，约 1 天）

1. `README.md` — 项目能干什么、技术栈、目录结构
2. `CLAUDE.md` — 精简版项目说明（更贴近代码现状）
3. `pom.xml` — 引入了哪些依赖（第 1 课）
4. `application.yml` — 怎么连数据库/中间件（第 1 课）
5. `src/main/resources/db/schema.sql` — 4 张表长什么样（第 10 课重点，先扫一眼）

### 第 2 步：按「数据流」从下往上看分层（第 2～7 课）

6. `LibraryApplication.java` — 启动类
7. `entity/` — 表对应的 Java 类（先看 `Book.java`）
8. `mapper/` — 数据访问接口（先看 `BookMapper.java`）
9. `service/` + `service/impl/` — 业务逻辑（先看 `UserServiceImpl`，再看 `BorrowServiceImpl`）
10. `controller/` — 接口层（先看 `BookController.java`）

### 第 3 步：看「横切组件」（第 8～9 课）

11. `common/result/` — 统一返回
12. `common/exception/` — 异常处理
13. `interceptor/JwtInterceptor.java` + `util/JwtUtil.java` + `util/UserContext.java` — 认证链路

### 第 4 步：看「中间件」（第 11～12 课）

14. `util/RedisService.java` + `common/config/RedisConfig.java` — Redis
15. `common/config/RabbitMQConfig.java` + `util/MessageProducer.java` + `service/impl/MessageConsumer.java` — RabbitMQ

### 第 5 步：看「微服务 + 前端」（第 13～14 课）

16. `notification-service/` — 独立通知微服务
17. `frontend/src/` — React 前端（按 `api/ → pages/ → router/ → store/` 顺序）

### 暂时不要碰的

- ❌ `target/`、`node_modules/`、`.gradle/`、`.mvn/` — 构建产物/依赖缓存
- ❌ Knife4j/Swagger 注解的每个参数细节 — 会用即可
- ❌ JVM 源码、Spring 源码、MySQL 源码 — 阶段四以后再考虑

## 七、每课学完的自检清单（对应「每个知识点要回答的 10 个问题」）

以后学任何技术（`@RestController`、`@Transactional`、Redis 缓存、RabbitMQ 死信队列……），都用这 10 问自检，答不上来就回去补：

1. **它是什么？**（一句话定义）
2. **为什么需要它？**（没有它会怎样）
3. **它解决了什么问题？**
4. **项目哪里用了它？**（能指出具体文件和行）
5. **如果不用它会怎么样？**
6. **它底层大概怎么工作？**（初级理解即可，不钻源码）
7. **有没有其他写法？**（如 `@Autowired` vs 构造器注入）
8. **面试官可能怎么问？**
9. **我应该掌握到什么程度？**（初级/中级/高级，明确当前只需到哪级）
10. **给我一个小练习？**（能自己动手改代码验证）
