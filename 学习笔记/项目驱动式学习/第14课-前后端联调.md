## 一、从项目代码开始

看前端怎么调用后端接口。以图书列表查询为例：

**页面组件（BookList.tsx）**：
```tsx
import { pageBooks } from '@/api/book'

const loadBooks = async () => {
  setLoading(true)
  try {
    const res = await pageBooks({ keyword, categoryId, pageNum, pageSize })
    setBooks(res.data.records)
    setTotal(res.data.total)
  } catch (error) {
    console.error('加载图书失败', error)
  } finally {
    setLoading(false)
  }
}
```

**API 层（api/book.ts）**：
```tsx
import { get, post, put, del } from './request'

export function pageBooks(params: BookQuery) {
  return get<PageResult<Book>>('/books', params)
}

export function getBookById(id: number) {
  return get<Book>(`/books/${id}`)
}

export function addBook(data: BookForm) {
  return post<void>('/books', data)
}
```

**Axios 封装（api/request.ts）**：
```tsx
import axios from 'axios'

const service = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || '/api',
  timeout: 15000,
})

// 请求拦截器：自动携带 Token
service.interceptors.request.use((config) => {
  const token = getToken()
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  return config
})

// 响应拦截器：统一处理响应和错误
service.interceptors.response.use(
  (response) => {
    const res = response.data
    if (res.code === 20000) {
      return response  // 成功
    }
    if (res.code === 40100) {
      // 未登录，跳登录页
      removeToken()
      window.location.href = '/login'
    }
    message.error(res.message || '请求失败')
    return Promise.reject(new Error(res.message))
  },
  (error) => {
    // HTTP 状态码错误处理
    if (error.response?.status === 401) { ... }
    if (error.response?.status === 500) { ... }
    return Promise.reject(error)
  }
)

// 封装通用请求方法
export function get<T>(url: string, params?: any) {
  return service.get(url, { params }).then(res => res.data)
}
export function post<T>(url: string, data?: any) {
  return service.post(url, data).then(res => res.data)
}
```

这就是前端请求的三层封装：**页面组件 → API 层 → Axios 封装**。

## 二、Axios 是什么？

Axios 是一个基于 Promise 的 HTTP 客户端，用于浏览器和 Node.js 中发送 HTTP 请求。

### 为什么用 Axios 而不是原生 fetch？

| 特性 | Axios | fetch |
|------|-------|-------|
| 请求/响应拦截器 | ✅ 支持 | ❌ 不支持（需要自己封装） |
| 自动转换 JSON | ✅ 自动 | ❌ 需要手动 `response.json()` |
| 请求取消 | ✅ 支持 | ❌ 不支持（用 AbortController） |
| 超时设置 | ✅ 支持 | ❌ 不支持（需要自己实现） |
| 错误处理 | ✅ HTTP 错误也 reject | ❌ 只有网络错误才 reject，HTTP 4xx/5xx 不 reject |
| 防 XSRF | ✅ 支持 | ❌ 不支持 |

项目用 Axios 主要是因为：拦截器（自动带 Token、统一错误处理）、自动 JSON 转换、更好的错误处理。

### Axios 的基本用法

```tsx
import axios from 'axios'

// GET 请求
axios.get('/api/books', { params: { pageNum: 1, pageSize: 10 } })
  .then(response => console.log(response.data))
  .catch(error => console.error(error))

// POST 请求
axios.post('/api/books', { title: '新书', author: '作者' })
  .then(response => console.log(response.data))

// async/await 写法（项目里用的）
const response = await axios.get('/api/books/1')
console.log(response.data)
```

## 三、Axios 实例创建

项目里没有直接用全局 axios，而是创建了一个实例：

```tsx
const service = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || '/api',
  timeout: 15000,
})
```

### 配置项说明

| 配置 | 说明 | 项目里的值 |
|------|------|-----------|
| `baseURL` | 请求的基础 URL，会自动拼接到每个请求的 URL 前面 | `import.meta.env.VITE_API_BASE_URL \|\| '/api'` |
| `timeout` | 请求超时时间（毫秒），超过则报错 | `15000`（15秒） |

### baseURL 的环境区分

项目里有两个环境配置文件：

**`.env.development`（开发环境）**：
```
VITE_API_BASE_URL=/api
```

**`.env.production`（生产环境）**：
```
VITE_API_BASE_URL=http://localhost:8080/api
```

- 开发环境：`baseURL = '/api'`，请求发到当前前端服务器（Vite 开发服务器），通过代理转发到后端（下面讲跨域时详细说）
- 生产环境：`baseURL = 'http://localhost:8080/api'`，直接请求后端地址

`import.meta.env` 是 Vite 提供的环境变量对象，`VITE_` 开头的变量会暴露给前端代码。

## 四、请求拦截器——自动携带 Token

```tsx
service.interceptors.request.use(
  (config) => {
    const token = getToken()  // 从 localStorage 取 Token
    if (token) {
      config.headers.Authorization = `Bearer ${token}`  // 加到请求头
    }
    return config  // 必须返回 config，否则请求不会发出
  },
  (error) => {
    console.error('请求错误:', error)
    return Promise.reject(error)
  }
)
```

### 请求拦截器的作用

请求拦截器在请求发出**之前**执行，可以修改请求配置：

1. **自动携带 Token**：从 localStorage 取出 Token，加到 `Authorization` 请求头，这样每个请求都自动带 Token，不需要在每个 API 方法里手动加
2. **统一添加请求头**：比如加 `Content-Type: application/json`
3. **请求参数处理**：比如对参数进行序列化、加密
4. **请求日志**：记录请求信息便于调试

### Token 存在哪？

看 `utils/auth.ts`：
```tsx
const TOKEN_KEY = 'library_token'

export function getToken(): string | null {
  return localStorage.getItem(TOKEN_KEY)
}

export function setToken(token: string): void {
  localStorage.setItem(TOKEN_KEY, token)
}

export function removeToken(): void {
  localStorage.removeItem(TOKEN_KEY)
}
```

Token 存在 `localStorage` 里：
- 登录成功后，`setToken(token)` 存到 localStorage
- 每次请求时，请求拦截器 `getToken()` 取出来加到请求头
- 退出登录或 Token 过期时，`removeToken()` 删除

### localStorage vs sessionStorage vs Cookie

| 存储方式 | 生命周期 | 大小 | 自动携带 | 项目里用 |
|---------|---------|------|---------|---------|
| localStorage | 永久存储，除非手动删除 | ~5MB | 否 | ✅ 存 Token |
| sessionStorage | 标签页关闭就清除 | ~5MB | 否 | 没用 |
| Cookie | 可设置过期时间 | ~4KB | 是（自动带在请求头） | 没用 |

项目用 localStorage 存 Token，因为：
- 持久化：关闭浏览器再打开还在，不用重新登录
- 前端可以手动读取（请求拦截器需要取 Token）
- Cookie 会自动携带，但项目用 JWT 放在 Authorization 头里，不需要 Cookie

## 五、响应拦截器——统一处理响应和错误

```tsx
service.interceptors.response.use(
  // 成功回调：HTTP 状态码 2xx 时执行
  (response) => {
    const res = response.data as ApiResponse

    // 业务成功：code === 20000
    if (res.code === 20000) {
      return response  // 返回完整 response，由封装方法提取 data
    }

    // 未登录或 Token 过期：code === 40100
    if (res.code === 40100) {
      message.error('登录已过期，请重新登录')
      removeToken()
      if (window.location.pathname !== '/login') {
        window.location.href = '/login'  // 跳登录页
      }
      return Promise.reject(new Error(res.message || '未登录'))
    }

    // 其他业务错误
    message.error(res.message || '请求失败')
    return Promise.reject(new Error(res.message || '请求失败'))
  },
  // 失败回调：HTTP 状态码 4xx/5xx 或网络错误时执行
  (error) => {
    if (error.response) {
      const status = error.response.status
      switch (status) {
        case 401:
          message.error('登录已过期，请重新登录')
          removeToken()
          window.location.href = '/login'
          break
        case 403:
          message.error('没有权限访问')
          break
        case 404:
          message.error('请求的资源不存在')
          break
        case 500:
          message.error('服务器内部错误')
          break
        default:
          message.error(error.response.data?.message || `请求失败 (${status})`)
      }
    } else if (error.request) {
      message.error('网络异常，请检查网络连接')
    } else {
      message.error('请求配置错误')
    }
    return Promise.reject(error)
  }
)
```

### 响应拦截器的两个回调

| 回调 | 触发时机 | 项目里的处理 |
|------|---------|-------------|
| `onFulfilled`（成功） | HTTP 状态码 2xx | 判断业务 code：20000 成功返回，40100 跳登录，其他弹错误提示 |
| `onRejected`（失败） | HTTP 状态码 4xx/5xx 或网络错误 | 根据 HTTP 状态码弹不同错误提示（401跳登录、403无权限、404不存在、500服务器错误、网络异常） |

### 为什么 HTTP 200 还要判断业务 code？

项目的设计是：**HTTP 状态码只表示传输层是否成功，业务成功/失败通过 `Result.code` 字段区分**。

- HTTP 200 + code=20000 → 业务成功
- HTTP 200 + code=42001 → 业务失败（图书不存在）
- HTTP 500 → 服务器内部错误（全局异常处理器的兜底）

所以响应拦截器里，即使 HTTP 200，也要判断 `res.code`，不是 20000 就当错误处理。

这和第8课讲的"业务异常返回 HTTP 200 + code 字段"是一致的。

### 封装的通用请求方法

```tsx
export function get<T = any>(url: string, params?: any): Promise<ApiResponse<T>> {
  return service.get(url, { params, ...config }).then((res) => res.data as ApiResponse<T>)
}

export function post<T = any>(url: string, data?: any): Promise<ApiResponse<T>> {
  return service.post(url, data, config).then((res) => res.data as ApiResponse<T>)
}
```

这些方法在 Axios 实例基础上又包了一层，`.then(res => res.data)` 直接取出响应体数据（`Result` 对象），这样页面组件里 `res.data` 就是业务数据了。

调用链：
```
页面组件: const res = await pageBooks(params)
    │
    ▼
API 层: return get<PageResult<Book>>('/books', params)
    │
    ▼
request.ts get(): return service.get(url, { params }).then(res => res.data)
    │
    ▼
Axios 实例 service: 发送请求
    │
    ├─ 请求拦截器：加 Token
    ├─ 发 HTTP 请求到后端
    └─ 响应拦截器：判断 code，处理错误
    │
    ▼
返回 ApiResponse<T> = { code, message, data, timestamp }
```

## 六、跨域问题

### 什么是跨域？

跨域是浏览器的**同源策略**限制：当一个网页的协议、域名、端口三者有一个不同，就属于跨域，浏览器会限制跨域请求。

项目里的情况：
- 前端开发服务器：`http://localhost:5173`（Vite 默认端口）
- 后端服务器：`http://localhost:8080`

端口不同（5173 vs 8080），所以前端直接请求后端会跨域。

### 项目里的两种解决方案

#### 方案1：开发环境——Vite 代理

看 `vite.config.ts`：
```ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],
  server: {
    port: 5173,
    proxy: {
      '/api': {
        target: 'http://localhost:8080',  // 代理目标：后端地址
        changeOrigin: true,                 // 改变请求头的 origin
      },
    },
  },
})
```

Vite 开发服务器代理的原理：
1. 前端请求 `http://localhost:5173/api/books`（同源，不跨域）
2. Vite 开发服务器收到请求，发现路径以 `/api` 开头
3. Vite 把请求转发到 `http://localhost:8080/api/books`（服务器之间请求，不受浏览器同源策略限制）
4. Vite 把后端响应返回给前端

这样前端感觉是在请求自己的服务器，实际上被代理到了后端，完美解决开发环境跨域。

#### 方案2：生产环境——后端 CORS 配置

看 `WebMvcConfig.java`：
```java
@Override
public void addCorsMappings(CorsRegistry registry) {
    registry.addMapping("/**")
            .allowedOriginPatterns("*")           // 允许所有来源
            .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
            .allowedHeaders("*")
            .allowCredentials(true)
            .maxAge(3600);
}
```

CORS（Cross-Origin Resource Sharing，跨域资源共享）是后端的解决方案：
- 后端在响应头里加 `Access-Control-Allow-Origin` 等字段
- 浏览器看到这些响应头，就允许跨域请求

项目里配置了：
- `allowedOriginPatterns("*")`：允许所有来源（生产环境应该限制为具体域名）
- `allowedMethods`：允许的 HTTP 方法
- `allowedHeaders("*")`：允许所有请求头
- `allowCredentials(true)`：允许携带凭证（Cookie、Authorization 头）
- `maxAge(3600)`：预检请求缓存 3600 秒，减少 OPTIONS 请求

### 预检请求（OPTIONS）

跨域请求时，浏览器会先发一个 **OPTIONS 预检请求**，询问服务器是否允许跨域：
- 简单请求（GET/POST + 简单头）：可能直接发，不需要预检
- 非简单请求（PUT/DELETE、自定义头如 Authorization）：必须先发 OPTIONS 预检

项目里的 JwtInterceptor 放行 OPTIONS 请求：
```java
if ("OPTIONS".equalsIgnoreCase(request.getMethod())) {
    return true;  // 放行预检请求，不需要 Token
}
```

因为 OPTIONS 预检请求不会带 Token，如果拦截了就会导致跨域请求失败。

## 七、一个 API 调用的完整流程

以**查询图书详情**为例，从前端点击到页面显示的完整流程：

```
用户点击"详情"按钮
    │
    ▼
BookList.tsx: handleDetail(book.id)
    │
    ▼
调用 getBookById(id)  (api/book.ts)
    │
    ▼
request.ts: get(`/books/${id}`)
    │
    ▼
Axios 实例 service.get(url)
    │
    ├─ 1. 请求拦截器执行
    │     ├─ getToken() 从 localStorage 取 Token
    │     └─ config.headers.Authorization = `Bearer ${token}`
    │
    ├─ 2. 发送 HTTP 请求
    │     ├─ 开发环境：http://localhost:5173/api/books/1 → Vite 代理 → http://localhost:8080/api/books/1
    │     └─ 生产环境：直接请求 http://localhost:8080/api/books/1
    │
    ▼
后端 Spring Boot 接收请求
    │
    ├─ 3. DispatcherServlet 接收，路径 /api/books/1
    ├─ 4. JwtInterceptor.preHandle
    │     ├─ 从请求头取 Authorization
    │     ├─ 提取 Token，验证签名和过期
    │     ├─ 解析用户信息，存入 UserContext
    │     └─ 放行
    │
    ├─ 5. BookController.getBookById(1)
    │     └─ 调用 bookService.getBookById(1)
    │
    ├─ 6. BookServiceImpl.getBookById(1)
    │     ├─ 先查 Redis 缓存（library:book:1）
    │     ├─ 缓存未命中，查 MySQL（SELECT * FROM book WHERE id=1 AND deleted=0）
    │     ├─ 转换为 BookVO（补充分类名称、是否可借）
    │     ├─ 写入 Redis 缓存（30分钟过期）
    │     └─ 返回 BookVO
    │
    ├─ 7. Controller 包装成 Result.success(bookVO)
    │     └─ { code: 20000, message: "操作成功", data: {...}, timestamp: ... }
    │
    ├─ 8. Jackson 序列化成 JSON
    │
    ├─ 9. JwtInterceptor.afterCompletion
    │     └─ UserContext.clear() 清除 ThreadLocal
    │
    ▼
HTTP 响应返回前端
    │
    ├─ 10. Axios 响应拦截器执行
    │     ├─ res.code === 20000 → 成功，返回 response
    │     └─ .then(res => res.data) 取出响应体
    │
    ▼
BookList.tsx: handleDetail 拿到 res
    │
    ├─ setDetailBook(res.data)  更新状态
    ├─ setDetailOpen(true)       打开详情弹窗
    │
    ▼
React 重新渲染，详情弹窗显示图书信息
```

## 八、本课必须记住的 7 件事

1. **前端请求三层封装**：页面组件 → API 层（api/book.ts）→ Axios 封装（api/request.ts），职责分离
2. **请求拦截器**：在请求发出前执行，自动从 localStorage 取 Token 加到 Authorization 请求头，不需要每个请求手动加
3. **响应拦截器**：在响应返回后执行，统一判断业务 code（20000成功、40100跳登录、其他弹错误），统一处理 HTTP 错误（401/403/404/500）
4. **跨域解决方案**：开发环境用 Vite 代理（前端请求自己的服务器，Vite 转发到后端），生产环境用后端 CORS 配置（WebMvcConfig.addCorsMappings）
5. **Token 存储**：存在 localStorage，登录成功后 setToken，请求拦截器 getToken 自动携带，退出/过期时 removeToken
6. **环境变量**：`.env.development` 和 `.env.production` 分别配置开发和生产的 API 地址，`VITE_` 开头的变量前端可访问
7. **完整流程**：用户操作 → 页面组件调用 API → Axios 拦截器加 Token → 发 HTTP 请求 → 后端拦截器验证 → Controller → Service → Mapper → 数据库 → 返回 Result → 前端拦截器处理 → 更新状态 → 页面渲染

## 十、自测题

### Q1：项目里前端请求后端的完整封装结构是什么？每一层的作用是什么？

<details>
<summary>点击查看答案</summary>

项目里前端请求分三层封装：

1. **页面组件层（pages/BookList.tsx）**：调用 API 层方法，处理响应数据，更新组件状态，触发页面渲染。比如 `loadBooks()` 里调用 `pageBooks()`，拿到数据后 `setBooks()` 更新表格。
2. **API 层（api/book.ts）**：定义具体的 API 方法，指定 URL 和请求方法，封装请求参数和返回类型。比如 `pageBooks(params)` 调用 `get('/books', params)`，`addBook(data)` 调用 `post('/books', data)`。
3. **Axios 封装层（api/request.ts）**：创建 Axios 实例（配置 baseURL、timeout），添加请求拦截器（自动携带 Token）和响应拦截器（统一处理业务 code 和 HTTP 错误），封装通用的 get/post/put/del 方法。

三层职责分离：页面组件只关心业务逻辑，API 层只关心接口定义，request.ts 只关心 HTTP 通信细节。这样修改 HTTP 配置（如加拦截器、改 baseURL）只需要改 request.ts，不影响业务代码。

</details>

### Q2：请求拦截器和响应拦截器分别做了什么？

<details>
<summary>点击查看答案</summary>

**请求拦截器（request interceptor）**：在请求发出之前执行，项目里做了：
1. 从 localStorage 取出 Token（`getToken()`）
2. 如果 Token 存在，加到请求头 `Authorization: Bearer <token>`
3. 返回 config（必须返回，否则请求不会发出）

作用：每个请求自动携带 Token，不需要在每个 API 方法里手动加。

**响应拦截器（response interceptor）**：在响应返回后、页面组件拿到数据之前执行，有两个回调：
1. **成功回调（HTTP 2xx）**：
   - 判断业务 code：`code === 20000` → 成功，返回 response
   - `code === 40100` → 未登录/Token过期，弹提示、删除 Token、跳登录页
   - 其他 code → 弹错误提示，reject
2. **失败回调（HTTP 4xx/5xx 或网络错误）**：
   - 根据 HTTP 状态码弹不同提示：401跳登录、403无权限、404不存在、500服务器错误
   - 网络错误（无 response）→ 提示"网络异常"
   - reject 错误

作用：统一处理响应和错误，页面组件不需要每个请求都写 try-catch 处理 401 跳转等逻辑，代码更简洁。

</details>

### Q3：什么是跨域？项目里怎么解决的？

<details>
<summary>点击查看答案</summary>

**跨域**：浏览器的同源策略限制，当请求的协议、域名、端口三者有一个不同，就属于跨域，浏览器会限制跨域请求（主要是限制读取响应，简单请求可能发出但读不到响应，非简单请求先发 OPTIONS 预检）。

项目里前端 `http://localhost:5173`，后端 `http://localhost:8080`，端口不同，所以跨域。

**项目里的两种解决方案**：

1. **开发环境：Vite 代理**（vite.config.ts）：
   - 配置 `proxy: { '/api': { target: 'http://localhost:8080', changeOrigin: true } }`
   - 前端请求 `http://localhost:5173/api/xxx`（同源，不跨域）
   - Vite 开发服务器把 `/api` 开头的请求转发到 `http://localhost:8080/api/xxx`
   - 服务器之间请求不受浏览器同源策略限制
   - 原理：前端请求自己的服务器，Vite 做代理转发

2. **生产环境：后端 CORS 配置**（WebMvcConfig.addCorsMappings）：
   - 后端在响应头加 `Access-Control-Allow-Origin` 等 CORS 头
   - 浏览器看到这些头就允许跨域请求
   - 项目配置了允许所有来源、所有方法、所有头、允许凭证
   - 注意：生产环境应该限制为具体域名，`*` 不安全

另外，JwtInterceptor 里放行 OPTIONS 预检请求（`if ("OPTIONS".equalsIgnoreCase(method)) return true`），因为预检请求不带 Token，如果拦截会导致跨域请求失败。

</details>

### Q4：Token 存在哪里？怎么自动携带到请求头？Token 过期了怎么处理？

<details>
<summary>点击查看答案</summary>

**Token 存储**：存在浏览器的 `localStorage` 里（utils/auth.ts），key 是 `library_token`。
- 登录成功后：`setToken(token)` 存入 localStorage
- 请求时：请求拦截器 `getToken()` 取出
- 退出/过期时：`removeToken()` 删除

**自动携带**：Axios 请求拦截器在每个请求发出前执行，从 localStorage 取出 Token，如果存在就加到请求头 `config.headers.Authorization = 'Bearer ' + token`。这样每个请求都自动带 Token，不需要在每个 API 方法里手动加。

**Token 过期处理**：
1. 后端 JwtInterceptor 验证 Token 过期，抛出 `TOKEN_EXPIRED` 异常
2. 全局异常处理器返回 `Result.error(40102, "Token 已过期")`
3. 前端响应拦截器判断 `code === 40100`（未登录/过期），执行：
   - 弹提示"登录已过期，请重新登录"
   - `removeToken()` 删除本地 Token
   - 跳转到登录页 `window.location.href = '/login'`
4. HTTP 状态码 401 也会在失败回调里做同样处理

另外，前端路由守卫（RequireAuth）也会检查登录状态，未登录时直接跳登录页，不需要等请求返回 401。

</details>

### Q5：从前端点击"查询图书"到页面显示数据，完整的流程是什么？

<details>
<summary>点击查看答案</summary>

完整流程（10步）：

1. **用户操作**：用户在搜索框输入关键词，点击"搜索"按钮
2. **页面组件**：`handleSearch()` 调用 `setPageNum(1)` 重置页码，然后调用 `loadBooks()`
3. **API 层**：`loadBooks()` 调用 `pageBooks({ keyword, categoryId, pageNum, pageSize })`，API 层调用 `get('/books', params)`
4. **请求拦截器**：Axios 请求拦截器从 localStorage 取 Token，加到 `Authorization` 请求头
5. **发送 HTTP 请求**：开发环境通过 Vite 代理转发到后端 `GET http://localhost:8080/api/books?keyword=Java&pageNum=1&pageSize=10`
6. **后端处理**：
   - DispatcherServlet 接收请求
   - JwtInterceptor 验证 Token，解析用户信息存入 UserContext，放行
   - BookController.pageBooks 接收参数，调用 BookService
   - BookServiceImpl 构建分页对象和 LambdaQueryWrapper，调用 MyBatis-Plus 分页查询
   - BookMapper 执行 SQL（SELECT * FROM book WHERE title LIKE '%Java%' AND deleted=0 LIMIT 0,10 + COUNT）
   - 结果转换成 BookVO，包装成 Result 返回

9. **页面组件更新状态**：`loadBooks()` 拿到 `res.data.records` 和 `res.data.total`，调用 `setBooks()` 和 `setTotal()` 更新状态
10. **React 重新渲染**：状态变化触发组件重新渲染，Table 组件显示新的图书列表数据，loading 状态设为 false

</details>

## 十一、面试题

### 面试题1：前后端分离项目怎么解决跨域问题？

> **答题要点**：
> 1. **跨域原因**：浏览器同源策略，协议/域名/端口不同就跨域。前后端分离项目前端（如 localhost:5173）和后端（如 localhost:8080）端口不同，所以跨域。
> 2. **开发环境：前端代理**（Vite/Webpack devServer proxy）：
>    - 配置代理规则，把 `/api` 开头的请求转发到后端地址
>    - 前端请求自己的开发服务器（同源），开发服务器转发到后端（服务器间请求不受同源策略限制）
>    - 项目里 vite.config.ts 配置了 `proxy: { '/api': { target: 'http://localhost:8080' } }`
> 3. **生产环境：后端 CORS**（Cross-Origin Resource Sharing）：
>    - 后端在响应头加 `Access-Control-Allow-Origin`、`Access-Control-Allow-Methods`、`Access-Control-Allow-Headers` 等
>    - 浏览器看到这些头就允许跨域请求读取响应
>    - 项目里 WebMvcConfig 实现 `addCorsMappings`，配置允许所有来源、方法、头，允许凭证
>    - 生产环境应该限制为具体域名，不要用 `*`
> 4. **其他方案**：
>    - **Nginx 反向代理**：前端和后端都通过 Nginx 访问，同源，不存在跨域
>    - **JSONP**：只支持 GET，已淘汰
>    - **postMessage**：页面间通信，不适合 API 请求
> 5. **预检请求**：非简单请求（PUT/DELETE、自定义头）会先发 OPTIONS 预检，后端需要正确响应 OPTIONS。项目里 JwtInterceptor 放行 OPTIONS 请求（不带 Token）。

### 面试题2：Axios 拦截器的原理和使用场景？

> **答题要点**：
> 1. **原理**：Axios 内部用 Promise 链实现拦截器。请求拦截器在 `dispatchRequest` 之前执行，响应拦截器在 `dispatchRequest` 之后执行。请求拦截器后添加的先执行（栈结构），响应拦截器先添加的先执行（队列结构）。
> 2. **请求拦截器使用场景**：
>    - 自动添加 Token/认证头（项目里 `config.headers.Authorization = 'Bearer ' + token`）
>    - 统一添加请求头（Content-Type、traceId 等）
>    - 请求参数处理（序列化、加密、时间戳）
>    - 请求日志/埋点
>    - 请求取消/重试逻辑
> 3. **响应拦截器使用场景**：
>    - 统一处理业务状态码（项目里 code=20000 成功，40100 跳登录，其他弹错误）
>    - 统一处理 HTTP 错误（401/403/404/500）
>    - 响应数据格式化/脱敏
>    - 响应日志
>    - 自动刷新 Token（401 时用 refreshToken 刷新后重试原请求）
> 4. **项目里的实现**：
>    - 请求拦截器：从 localStorage 取 Token 加到 Authorization 头
>    - 响应拦截器成功回调：判断业务 code，20000 返回，40100 删 Token 跳登录，其他弹错误 reject
>    - 响应拦截器失败回调：根据 HTTP 状态码弹不同错误提示，401 跳登录
> 5. **注意**：请求拦截器必须 return config，否则请求不会发出；响应拦截器可以 return response 或 Promise.reject(error)。
