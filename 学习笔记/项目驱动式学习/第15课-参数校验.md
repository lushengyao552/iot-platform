# 第15课：参数校验——@Valid、@Validated、自定义校验注解

> **本课目标**：搞懂 Spring Boot 里怎么做参数校验，理解 `@Valid` 和 `@Validated` 的区别、常用校验注解、分组校验、自定义校验注解，以及校验失败后的全局异常处理。

## 一、从项目代码开始

看 `BookAddDTO` 里的校验注解：

```java
@Data
public class BookAddDTO {

    @NotBlank(message = "书名不能为空")
    @Size(max = 100, message = "书名长度不能超过100")
    private String title;

    @NotBlank(message = "作者不能为空")
    @Size(max = 50, message = "作者长度不能超过50")
    private String author;

    @Size(max = 20, message = "ISBN长度不能超过20")
    private String isbn;

    @Size(max = 100, message = "出版社长度不能超过100")
    private String publisher;

    @NotNull(message = "分类ID不能为空")
    private Long categoryId;

    @DecimalMin(value = "0.00", message = "价格不能为负数")
    private BigDecimal price;

    @NotNull(message = "库存不能为空")
    @Min(value = 0, message = "库存不能为负数")
    private Integer stock;

    @Size(max = 500, message = "简介长度不能超过500")
    private String description;
}
```

再看 Controller 里怎么触发校验：

```java
@PostMapping
public Result<BookVO> addBook(@RequestBody @Valid BookAddDTO addDTO) {
    BookVO bookVO = bookService.addBook(addDTO);
    return Result.success(bookVO);
}

@PutMapping("/{id}")
public Result<BookVO> updateBook(
        @PathVariable Long id,
        @RequestBody @Valid BookUpdateDTO updateDTO) {
    BookVO bookVO = bookService.updateBook(id, updateDTO);
    return Result.success(bookVO);
}
```

关键点：`@RequestBody @Valid BookAddDTO addDTO`——`@Valid` 注解告诉 Spring：在把请求体 JSON 转成 BookAddDTO 对象后，对这个对象做参数校验。如果校验失败，会抛出 `MethodArgumentNotValidException`。

## 二、为什么需要参数校验？

### 不做校验会怎样？

如果不做参数校验，用户可以传：
- `title = null` → 数据库报 NOT NULL 约束错误（500 错误，不友好）
- `stock = -100` → 库存变成负数，业务逻辑错误
- `price = -999` → 价格变成负数
- `title = "a".repeat(10000)` → 数据库字段超长报错，或者浪费存储

### 参数校验的作用

1. **提前拦截非法参数**：在 Controller 层就拦截，不进入 Service 层，减少无效业务处理
2. **友好的错误提示**：返回明确的错误信息（"书名不能为空"），而不是数据库报错
3. **安全防护**：防止恶意输入（超长字符串、负数、SQL 注入等）
4. **业务规则保障**：确保数据符合业务规则（库存不能为负、价格不能为负）

### 校验分层

| 层级 | 校验内容 | 项目里的做法 |
|------|---------|-------------|
| **Controller 层** | 格式校验（非空、长度、范围、格式） | `@Valid` + 注解（@NotBlank、@Size、@Min 等） |
| **Service 层** | 业务规则校验（库存是否足够、是否已借阅、分类是否存在） | 代码里手动判断，抛 BusinessException |
| **数据库层** | 约束校验（NOT NULL、UNIQUE、外键、字段长度） | schema.sql 里的约束 |

三层校验各有侧重：Controller 层做格式校验，Service 层做业务校验，数据库做最终兜底。项目里主要用 Controller 层的注解校验 + Service 层的业务校验。

## 三、常用校验注解

这些注解来自 `jakarta.validation.constraints`（Spring Boot 3.x 用 jakarta，2.x 用 javax）。

### 非空校验

| 注解 | 作用 | 适用类型 | 示例 |
|------|------|---------|------|
| `@NotNull` | 不能为 null | 任意类型 | `@NotNull(message = "分类ID不能为空") Long categoryId` |
| `@NotBlank` | 不能为 null，且去掉首尾空格后长度 > 0 | String | `@NotBlank(message = "书名不能为空") String title` |
| `@NotEmpty` | 不能为 null，且长度 > 0 | String、Collection、Map、数组 | `@NotEmpty List<String> tags` |

**区别**：
- `@NotNull`：只判断 null，空字符串 `""` 是合法的
- `@NotBlank`：判断 null + 空字符串 + 全空格，`"  "` 不合法
- `@NotEmpty`：判断 null + 长度为 0，`""` 不合法，但 `"  "` 合法（长度 > 0）

项目里书名用 `@NotBlank`（不能是空白），分类 ID 用 `@NotNull`（Long 类型不能用 NotBlank）。

### 长度/大小校验

| 注解 | 作用 | 示例 |
|------|------|------|
| `@Size(min, max)` | 字符串长度、集合大小、数组长度在范围内 | `@Size(max = 100) String title` |
| `@Length(min, max)` | 字符串长度（Hibernate Validator 扩展，和 @Size 类似） | 项目没用 |

### 数值范围校验

| 注解 | 作用 | 示例 |
|------|------|------|
| `@Min(value)` | 数值 >= value | `@Min(value = 0) Integer stock` |
| `@Max(value)` | 数值 <= value | `@Max(value = 10000) Integer stock` |
| `@DecimalMin(value)` | 数值 >= value（支持 BigDecimal） | `@DecimalMin("0.00") BigDecimal price` |
| `@DecimalMax(value)` | 数值 <= value（支持 BigDecimal） | 项目没用 |
| `@Positive` | 正数（> 0） | 项目没用 |
| `@PositiveOrZero` | 正数或零（>= 0） | 项目没用 |
| `@Negative` | 负数（< 0） | 项目没用 |

### 格式校验

| 注解 | 作用 | 示例 |
|------|------|------|
| `@Email` | 邮箱格式 | 项目里 User 注册可以用 |
| `@Pattern(regexp)` | 正则表达式匹配 | `@Pattern(regexp = "^1[3-9]\\d{9}$") String phone` |
| `@URL` | URL 格式 | 项目没用 |

### 其他

| 注解 | 作用 |
|------|------|
| `@AssertTrue` | 必须为 true |
| `@AssertFalse` | 必须为 false |
| `@Future` | 必须是未来的日期 |
| `@Past` | 必须是过去的日期 |
| `@Valid` | 级联校验（嵌套对象） |

## 四、@Valid 和 @Validated 的区别

这是面试高频考点。

| 特性 | `@Valid` | `@Validated` |
|------|----------|-------------|
| 来源 | Jakarta Bean Validation（标准） | Spring 框架（扩展） |
| 可用位置 | 方法参数、字段、构造器、方法返回值 | 类、方法、方法参数 |
| 分组校验 | ❌ 不支持 | ✅ 支持（`groups` 属性） |
| 级联校验（嵌套对象） | ✅ 支持（用在字段上） | ❌ 不支持（需要配合 @Valid） |
| 校验失败异常 | `MethodArgumentNotValidException`（RequestBody）/ `ConstraintViolationException`（普通参数） | `ConstraintViolationException` |

### 项目里的用法

项目里 Controller 用的是 `@Valid`：
```java
public Result<BookVO> addBook(@RequestBody @Valid BookAddDTO addDTO)
```

因为 BookAddDTO 是 `@RequestBody` 的对象，用 `@Valid` 触发校验，校验失败抛 `MethodArgumentNotValidException`，由全局异常处理器处理。

### 什么时候用 @Validated？

1. **分组校验**：同一个 DTO 在不同场景下校验规则不同。比如新增时 ID 不需要，更新时 ID 必须有
2. **方法级别的普通参数校验**：直接在 Controller 方法参数上加注解（如 `@RequestParam @Min(1) Integer pageNum`），需要在类上加 `@Validated`

### 分组校验示例

```java
// 定义分组接口
public interface AddGroup {}
public interface UpdateGroup {}

@Data
public class BookDTO {
    // 新增时 ID 为空，更新时 ID 必须有
    @NotNull(groups = UpdateGroup.class, message = "更新时ID不能为空")
    @Null(groups = AddGroup.class, message = "新增时ID必须为空")
    private Long id;

    // 两个分组都校验
    @NotBlank(groups = {AddGroup.class, UpdateGroup.class}, message = "书名不能为空")
    private String title;
}

// Controller 指定分组
@PostMapping
public Result add(@RequestBody @Validated(AddGroup.class) BookDTO dto) { ... }

@PutMapping
public Result update(@RequestBody @Validated(UpdateGroup.class) BookDTO dto) { ... }
```

项目里没有用分组校验，而是用了两个独立的 DTO（BookAddDTO 和 BookUpdateDTO），这也是一种常见做法，更清晰。

## 五、校验失败的全局异常处理

看 `GlobalExceptionHandler` 里怎么处理校验异常：

```java
@RestControllerAdvice
@Slf4j
public class GlobalExceptionHandler {

    // 处理 @Valid @RequestBody 校验失败
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValidationException(MethodArgumentNotValidException e) {
        // 从异常中取出第一个校验错误的信息
        String message = e.getBindingResult().getFieldErrors().stream()
                .findFirst()
                .map(FieldError::getDefaultMessage)
                .orElse("参数校验失败");
        log.warn("参数校验失败: {}", message);
        return Result.error(ResultCode.PARAM_ERROR.getCode(), message);
    }

    // 处理 @Validated 普通参数校验失败
    @ExceptionHandler(ConstraintViolationException.class)
    public Result<Void> handleConstraintViolationException(ConstraintViolationException e) {
        String message = e.getConstraintViolations().stream()
                .findFirst()
                .map(ConstraintViolation::getMessage)
                .orElse("参数校验失败");
        log.warn("参数校验失败: {}", message);
        return Result.error(ResultCode.PARAM_ERROR.getCode(), message);
    }
}
```

### 校验失败的响应

当用户传了空书名时，返回：
```json
{
  "code": 40000,
  "message": "书名不能为空",
  "data": null,
  "timestamp": "2026-09-02T10:00:00"
}
```

前端响应拦截器收到 code != 20000，弹出"书名不能为空"的错误提示。

### 为什么取第一个错误？

一个请求可能有多个字段校验失败（书名空 + 库存负 + 价格负），如果全部返回，前端需要处理多个错误。项目里取第一个错误，简单直接，用户改完一个再提示下一个。

如果需要返回所有错误，可以把所有错误信息拼接起来，或者返回一个错误列表。

## 六、自定义校验注解

当内置注解不够用时，可以自定义校验注解。比如项目里可以加一个"ISBN 格式校验"。

### 6.1 自定义校验注解

```java
// 自定义注解：校验 ISBN 格式
@Target({ElementType.FIELD, ElementType.PARAMETER})
@Retention(RetentionPolicy.RUNTIME)
@Constraint(validatedBy = IsbnValidator.class)  // 指定校验器
public @interface Isbn {
    String message() default "ISBN格式不正确";
    Class<?>[] groups() default {};
    Class<? extends Payload>[] payload() default {};
}
```

三个必填属性：
- `message()`：校验失败的提示信息
- `groups()`：分组
- `payload()`：负载（一般不用）

### 6.2 自定义校验器

```java
public class IsbnValidator implements ConstraintValidator<Isbn, String> {

    // ISBN-10 或 ISBN-13 的简单正则
    private static final Pattern ISBN_PATTERN = Pattern.compile("^(?:ISBN(?:-1[03])?:? )?(?=[0-9X]{10}$|(?=(?:[0-9]+[- ]){3})[- 0-9X]{13}$|97[89][0-9]{10}$|(?=(?:[0-9]+[- ]){4})[- 0-9]{17}$)");

    @Override
    public void initialize(Isbn constraintAnnotation) {
        // 初始化，可以从注解里取参数
    }

    @Override
    public boolean isValid(String value, ConstraintValidatorContext context) {
        if (value == null || value.isEmpty()) {
            return true;  // 空值由 @NotBlank 校验，这里只校验格式
        }
        return ISBN_PATTERN.matcher(value).matches();
    }
}
```

### 6.3 使用自定义注解

```java
@Data
public class BookAddDTO {
    @Isbn(message = "ISBN格式不正确（应为10位或13位）")
    private String isbn;
}
```

项目里目前没有自定义校验注解，这是可以扩展的点。

## 七、级联校验（嵌套对象）

如果 DTO 里嵌套了另一个对象，需要用 `@Valid` 触发嵌套校验：

```java
@Data
public class OrderDTO {
    @NotBlank(message = "订单号不能为空")
    private String orderNo;

    @Valid  // 级联校验：触发 OrderItemDTO 里的校验注解
    @NotEmpty(message = "订单项不能为空")
    private List<OrderItemDTO> items;
}

@Data
public class OrderItemDTO {
    @NotNull(message = "商品ID不能为空")
    private Long productId;

    @Min(value = 1, message = "数量至少为1")
    private Integer quantity;
}
```

项目里的 DTO 都是扁平结构，没有嵌套对象，所以没用级联校验。

## 八、本课必须记住的 7 件事

1. **参数校验三层**：Controller 层格式校验（@Valid 注解）、Service 层业务校验（手动判断抛异常）、数据库层约束兜底
2. **常用注解**：@NotNull（非空）、@NotBlank（非空白字符串）、@Size（长度）、@Min/@Max（数值范围）、@DecimalMin（BigDecimal范围）、@Email（邮箱）、@Pattern（正则）
3. **@Valid vs @Validated**：@Valid 是标准注解，支持级联校验；@Validated 是 Spring 扩展，支持分组校验。项目里用 @Valid 校验 RequestBody
4. **校验失败异常**：@Valid @RequestBody 校验失败抛 MethodArgumentNotValidException；@Validated 普通参数校验失败抛 ConstraintViolationException，都由全局异常处理器统一处理
5. **分组校验**：同一个 DTO 不同场景校验规则不同时用，@Validated(AddGroup.class) 指定分组。项目里用两个独立 DTO（Add/Update）代替分组
6. **自定义校验注解**：内置注解不够用时，定义 @Constraint 注解 + 实现 ConstraintValidator 接口
7. **级联校验**：嵌套对象字段上加 @Valid，触发嵌套对象里的校验

## 十、自测题

### Q1：@NotNull、@NotBlank、@NotEmpty 有什么区别？

<details>
<summary>点击查看答案</summary>

- **@NotNull**：值不能为 null。适用于任意类型（String、Integer、对象等）。空字符串 `""` 是合法的（因为不是 null）。
- **@NotBlank**：值不能为 null，且去掉首尾空格后长度必须 > 0。只适用于 String。`""` 和 `"  "` 都不合法。
- **@NotEmpty**：值不能为 null，且长度/大小必须 > 0。适用于 String、Collection、Map、数组。`""` 不合法，但 `"  "` 合法（长度 > 0）。

选择建议：
- 字符串字段（如书名、作者）：用 @NotBlank（最严格，防止全空格）
- 包装类型（如 Long categoryId、Integer stock）：用 @NotNull
- 集合/数组：用 @NotEmpty
- 项目里书名用 @NotBlank，分类ID用 @NotNull，就是这个原则。

</details>

### Q3：参数校验失败后，项目里是怎么处理的？返回什么？

<details>
<summary>点击查看答案</summary>

项目里用全局异常处理器（GlobalExceptionHandler）统一处理校验异常：

1. **@Valid @RequestBody 校验失败**：抛 `MethodArgumentNotValidException`
   - 处理器从异常的 BindingResult 里取出第一个 FieldError 的 defaultMessage
   - 返回 `Result.error(40000, "书名不能为空")`

2. **@Validated 普通参数校验失败**：抛 `ConstraintViolationException`
   - 处理器从 ConstraintViolations 里取出第一个 violation 的 message
   - 返回同样格式的错误

返回的 JSON：
```json
{
  "code": 40000,
  "message": "书名不能为空",
  "data": null,
  "timestamp": "2026-09-02T10:00:00"
}
```

前端响应拦截器收到 code != 20000，弹出 message 对应的错误提示（"书名不能为空"）。

**为什么取第一个错误**：一个请求可能多个字段校验失败，取第一个简单直接，用户改完一个再提示下一个。如果需要返回所有错误，可以拼接所有错误信息或返回错误列表。

</details>

### Q4：怎么实现一个自定义校验注解？

<details>
<summary>点击查看答案</summary>

实现自定义校验注解分两步：

**1. 定义注解**：
```java
@Target({ElementType.FIELD, ElementType.PARAMETER})
@Retention(RetentionPolicy.RUNTIME)
@Constraint(validatedBy = IsbnValidator.class)  // 指定校验器
public @interface Isbn {
    String message() default "ISBN格式不正确";     // 校验失败提示
    Class<?>[] groups() default {};                // 分组（必填）
    Class<? extends Payload>[] payload() default {}; // 负载（必填，一般不用）
}
```

**2. 实现校验器**：
```java
public class IsbnValidator implements ConstraintValidator<Isbn, String> {
    private static final Pattern PATTERN = Pattern.compile("^[0-9-]{10,17}$");

    @Override
    public void initialize(Isbn annotation) {
        // 初始化，可以从注解取参数
    }

    @Override
    public boolean isValid(String value, ConstraintValidatorContext context) {
        if (value == null || value.isEmpty()) {
            return true;  // 空值由 @NotBlank 负责，这里只校验格式
        }
        return PATTERN.matcher(value).matches();
    }
}
```

**3. 使用**：
```java
@Isbn(message = "ISBN格式不正确")
private String isbn;
```

关键点：
- 注解必须有 message、groups、payload 三个属性
- 用 @Constraint(validatedBy = XxxValidator.class) 指定校验器
- 校验器实现 ConstraintValidator<注解类型, 校验值类型> 接口
- isValid 方法返回 true 表示校验通过，false 表示失败
- 空值一般返回 true（交给 @NotBlank/@NotNull 处理），避免重复校验

</details>

### Q5：参数校验应该放在哪一层？Controller 层和 Service 层校验有什么区别？

<details>
<summary>点击查看答案</summary>

参数校验分三层，各有侧重：

**1. Controller 层（格式校验）**：
- 校验内容：非空、长度、数值范围、格式（邮箱、手机号、正则）
- 实现方式：@Valid + 注解（@NotBlank、@Size、@Min、@Email 等）
- 特点：声明式，注解驱动，自动触发，校验失败抛异常由全局处理器处理
- 项目里：BookAddDTO 上的 @NotBlank、@Size、@Min、@DecimalMin 等

**2. Service 层（业务规则校验）**：
- 校验内容：业务逻辑相关的规则，如库存是否足够、是否已借阅、分类是否存在、用户是否有权限
- 实现方式：代码里手动 if 判断，抛 BusinessException
- 特点：需要查询数据库或上下文，逻辑复杂，注解无法表达
- 项目里：BorrowServiceImpl 里检查"图书是否存在"、"库存是否>0"、"用户是否已借阅此书"、"借阅数量是否超限"

**3. 数据库层（约束兜底）**：
- 校验内容：NOT NULL、UNIQUE、外键、字段长度、CHECK 约束
- 实现方式：建表时定义约束
- 特点：最终兜底，防止前两层漏网之鱼

**区别总结**：
- Controller 层校验是"格式对不对"（静态规则，不需要查数据库）
- Service 层校验是"业务合不合理"（动态规则，需要查数据库/上下文）
- 两层都需要，不能互相替代。Controller 层拦截格式错误，Service 层拦截业务错误。

项目里的例子：新增图书时，Controller 层校验"书名不能为空、库存不能为负"（格式），Service 层校验"分类ID是否存在"（业务，需要查数据库）。

## 十一、面试题

### 面试题1：Spring Boot 参数校验怎么做的？@Valid 和 @Validated 的区别？

> **答题要点**：
> 1. **实现方式**：Spring Boot 集成 Jakarta Bean Validation（Hibernate Validator 实现），在 DTO 字段上加校验注解（@NotBlank、@Size、@Min、@Email、@Pattern 等），在 Controller 方法参数上加 @Valid 或 @Validated 触发校验。
> 2. **校验失败处理**：@Valid @RequestBody 校验失败抛 MethodArgumentNotValidException，@Validated 普通参数校验失败抛 ConstraintViolationException，由 @RestControllerAdvice 全局异常处理器统一捕获，返回友好的错误信息。
> 3. **@Valid vs @Validated**：
>    - @Valid：Jakarta 标准注解，支持级联校验（嵌套对象字段加 @Valid），不支持分组校验
>    - @Validated：Spring 扩展注解，支持分组校验（groups 属性），不支持级联校验（需配合 @Valid），可用在类/方法/参数上
>    - 项目里用 @Valid 校验 RequestBody，因为不需要分组，用两个独立 DTO（Add/Update）区分场景
> 4. **常用注解**：@NotNull（非空）、@NotBlank（非空白字符串）、@NotEmpty（非空集合/字符串）、@Size（长度）、@Min/@Max（数值范围）、@DecimalMin/@DecimalMax（BigDecimal）、@Email（邮箱）、@Pattern（正则）、@Positive/@Negative（正负）
> 5. **自定义校验**：内置注解不够用时，定义 @Constraint 注解 + 实现 ConstraintValidator 接口，如自定义 @Phone、@Isbn 校验
> 6. **校验分层**：Controller 层做格式校验（注解），Service 层做业务规则校验（手动判断抛异常），数据库层做约束兜底

### 面试题2：参数校验失败的异常怎么处理？怎么返回友好的错误信息？

> **答题要点**：
> 1. **全局异常处理器**：用 @RestControllerAdvice + @ExceptionHandler 统一捕获校验异常
> 2. **两种校验异常**：
>    - MethodArgumentNotValidException：@Valid @RequestBody 校验失败，从 e.getBindingResult().getFieldErrors() 取字段错误
>    - ConstraintViolationException：@Validated 普通参数校验失败，从 e.getConstraintViolations() 取错误
> 3. **错误信息提取**：取第一个错误的 defaultMessage（如"书名不能为空"），或拼接所有错误信息
> 4. **统一返回格式**：返回 Result 对象，code=40000（参数错误），message=具体错误信息
> 5. **前端处理**：响应拦截器判断 code != 20000，弹出 message 错误提示
> 6. **示例代码**：
> ```java
> @ExceptionHandler(MethodArgumentNotValidException.class)
> public Result<Void> handleValidation(MethodArgumentNotValidException e) {
>     String message = e.getBindingResult().getFieldErrors().stream()
>         .findFirst().map(FieldError::getDefaultMessage).orElse("参数校验失败");
>     return Result.error(40000, message);
> }
> ```
> 7. **进阶**：可以返回所有字段的错误（Map<字段名, 错误信息>），方便前端在每个表单字段下方显示错误；也可以用 @ControllerAdvice 配合 MessageSource 做国际化错误信息
