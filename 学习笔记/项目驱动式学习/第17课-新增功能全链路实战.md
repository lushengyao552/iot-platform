> **本课目标**：通过完整实现一个"图书评论"功能，带你走一遍从需求分析、数据库设计、后端代码、前端页面到测试的全流程。学完这课，你应该能独立为项目新增任何功能。

## 一、需求分析

### 功能需求

用户可以对图书发表评论，包括：
1. 查看某本图书的评论列表（分页）
2. 登录用户发表评论（评分 1-5 星 + 评论内容）
3. 评论作者可以删除自己的评论
4. 管理员可以删除任何评论

### 非功能需求
- 评论内容不能为空，长度不超过 500 字
- 评分必须是 1-5 的整数
- 评论列表按时间倒序排列
- 评论需要关联用户信息（用户名）

## 二、数据库设计

### 2.1 建表 SQL

在 `schema.sql` 里新增评论表：

```sql
-- ============================================================
-- 图书评论表
-- ============================================================
CREATE TABLE IF NOT EXISTS book_comment (
    id          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '评论ID',
    book_id     BIGINT       NOT NULL COMMENT '图书ID',
    user_id     BIGINT       NOT NULL COMMENT '用户ID',
    rating      TINYINT      NOT NULL COMMENT '评分(1-5星)',
    content     VARCHAR(500) NOT NULL COMMENT '评论内容',
    deleted     TINYINT      NOT NULL DEFAULT 0 COMMENT '是否删除(0-否 1-是)',
    create_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (id),
    KEY idx_book_id (book_id),          -- 按图书查询评论
    KEY idx_user_id (user_id),          -- 按用户查询评论
    KEY idx_create_time (create_time)   -- 按时间排序
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='图书评论表';
```

### 2.2 设计说明

| 字段 | 类型 | 说明 | 为什么这么设计 |
|------|------|------|--------------|
| id | BIGINT | 主键，自增 | 和项目其他表保持一致 |
| book_id | BIGINT | 图书ID，外键关联 book.id | 评论属于哪本书，加索引（按图书查评论是高频查询） |
| user_id | BIGINT | 用户ID，外键关联 sys_user.id | 谁发的评论，加索引 |
| rating | TINYINT | 评分 1-5 | 用 TINYINT 节省空间，1-5 足够 |
| content | VARCHAR(500) | 评论内容 | 500 字足够，VARCHAR 变长存储 |
| deleted | TINYINT | 逻辑删除 | 和项目其他表保持一致，用逻辑删除 |
| create_time / update_time | DATETIME | 时间戳 | MyBatis-Plus 自动填充 |

### 2.3 索引设计

- `idx_book_id`：按图书ID查询评论列表（`WHERE book_id = ? ORDER BY create_time DESC`），高频查询，必须加
- `idx_user_id`：按用户查询评论（如"我的评论"），加索引
- `idx_create_time`：按时间排序，加索引

注意：实际查询是 `WHERE book_id = ? ORDER BY create_time DESC`，可以建联合索引 `idx_book_time(book_id, create_time)` 更好，因为查询条件和排序字段都在索引里。这里为了简单分开建了，生产项目建议联合索引。

### 3.6 Service 接口和实现

```java
// 接口
public interface BookCommentService {
    IPage<CommentVO> pageComments(Integer pageNum, Integer pageSize, Long bookId);
    CommentVO addComment(CommentAddDTO addDTO);
    void deleteComment(Long commentId);
}
```

```java
// 实现
@Service
@RequiredArgsConstructor
@Slf4j
public class BookCommentServiceImpl implements BookCommentService {

    private final BookCommentRepository commentRepository;
    private final BookRepository bookRepository;

    @Override
    public IPage<CommentVO> pageComments(Integer pageNum, Integer pageSize, Long bookId) {
        Page<CommentVO> page = new Page<>(pageNum, pageSize);
        IPage<CommentVO> result = commentRepository.selectCommentPage(page, bookId);

        // 补充 canDelete 字段
        Long currentUserId = UserContext.getCurrentUserId();
        String currentUserRole = UserContext.getCurrentUserRole();
        result.getRecords().forEach(comment -> {
            boolean canDelete = comment.getUserId().equals(currentUserId)
                    || "ADMIN".equals(currentUserRole);
            comment.setCanDelete(canDelete);
        });

        return result;
    }

    @Override
    public CommentVO addComment(CommentAddDTO addDTO) {
        // 1. 校验图书是否存在
        Book book = bookRepository.getById(addDTO.getBookId());
        if (book == null || book.getDeleted() == 1) {
            throw new BusinessException(ResultCode.BOOK_NOT_FOUND);
        }

        // 2. 构建评论对象
        BookComment comment = new BookComment();
        comment.setBookId(addDTO.getBookId());
        comment.setUserId(UserContext.getCurrentUserId());
        comment.setRating(addDTO.getRating());
        comment.setContent(addDTO.getContent());

        // 3. 保存
        commentRepository.save(comment);
        log.info("用户发表评论, userId={}, bookId={}, commentId={}",
                comment.getUserId(), comment.getBookId(), comment.getId());

        // 4. 返回 VO
        CommentVO vo = new CommentVO();
        BeanUtils.copyProperties(comment, vo);
        vo.setUsername(UserContext.getCurrentUsername());
        vo.setCanDelete(true);  // 自己发的评论可以删除
        return vo;
    }

    @Override
    public void deleteComment(Long commentId) {
        // 1. 校验评论是否存在
        BookComment comment = commentRepository.getById(commentId);
        if (comment == null || comment.getDeleted() == 1) {
            throw new BusinessException(ResultCode.PARAM_ERROR.getCode(), "评论不存在");
        }

        // 2. 权限校验：只能删除自己的评论，管理员可以删除任何评论
        Long currentUserId = UserContext.getCurrentUserId();
        String currentUserRole = UserContext.getCurrentUserRole();
        if (!comment.getUserId().equals(currentUserId) && !"ADMIN".equals(currentUserRole)) {
            throw new BusinessException(ResultCode.NO_PERMISSION);
        }

        // 3. 逻辑删除
        commentRepository.removeById(commentId);
        log.info("删除评论, commentId={}, operator={}", commentId, currentUserId);
    }
}
```

### 3.7 Controller

```java
@RestController
@RequestMapping("/comments")
@RequiredArgsConstructor
@Slf4j
public class BookCommentController {

    private final BookCommentService commentService;

    // 分页查询评论列表
    @GetMapping
    public Result<IPage<CommentVO>> pageComments(
            @RequestParam(defaultValue = "1") Integer pageNum,
            @RequestParam(defaultValue = "10") Integer pageSize,
            @RequestParam Long bookId) {
        IPage<CommentVO> page = commentService.pageComments(pageNum, pageSize, bookId);
        return Result.success(page);
    }

    // 发表评论
    @PostMapping
    public Result<CommentVO> addComment(@RequestBody @Valid CommentAddDTO addDTO) {
        CommentVO vo = commentService.addComment(addDTO);
        return Result.success(vo);
    }

    // 删除评论
    @DeleteMapping("/{id}")
    public Result<Void> deleteComment(@PathVariable Long id) {
        commentService.deleteComment(id);
        return Result.success();
    }
}
```

### 4.3 评论组件（`components/CommentList.tsx`）

```tsx
import { useEffect, useState } from 'react'
import { List, Button, Input, Rate, message, Popconfirm, Pagination } from 'antd'
import { pageComments, addComment, deleteComment } from '@/api/comment'
import { useUserStore } from '@/store/userStore'

interface Props {
  bookId: number
}

export default function CommentList({ bookId }: Props) {
  const { user } = useUserStore()
  const [comments, setComments] = useState<Comment[]>([])
  const [total, setTotal] = useState(0)
  const [pageNum, setPageNum] = useState(1)
  const [pageSize] = useState(10)
  const [loading, setLoading] = useState(false)

  // 评论表单
  const [rating, setRating] = useState(5)
  const [content, setContent] = useState('')
  const [submitting, setSubmitting] = useState(false)

  // 加载评论列表
  const loadComments = async () => {
    setLoading(true)
    try {
      const res = await pageComments({ bookId, pageNum, pageSize })
      setComments(res.data.records)
      setTotal(res.data.total)
    } catch (e) {
      console.error('加载评论失败', e)
    } finally {
      setLoading(false)
    }
  }

  useEffect(() => {
    loadComments()
  }, [bookId, pageNum])

  // 发表评论
  const handleSubmit = async () => {
    if (!content.trim()) {
      message.warning('请输入评论内容')
      return
    }
    setSubmitting(true)
    try {
      await addComment({ bookId, rating, content })
      message.success('评论发表成功')
      setContent('')
      setRating(5)
      setPageNum(1)
      loadComments()
    } catch (e) {
      console.error('发表评论失败', e)
    } finally {
      setSubmitting(false)
    }
  }

  // 删除评论
  const handleDelete = async (id: number) => {
    try {
      await deleteComment(id)
      message.success('删除成功')
      loadComments()
    } catch (e) {
      console.error('删除评论失败', e)
    }
  }

  return (
    <div style={{ marginTop: 24 }}>
      <h3>评论 ({total})</h3>

      {/* 发表评论（登录用户可见） */}
      {user && (
        <div style={{ marginBottom: 24, padding: 16, background: '#fafafa', borderRadius: 8 }}>
          <Rate value={rating} onChange={setRating} />
          <Input.TextArea
            rows={3}
            value={content}
            onChange={(e) => setContent(e.target.value)}
            placeholder="写下你的评论..."
            maxLength={500}
            showCount
            style={{ marginTop: 8 }}
          />
          <Button
            type="primary"
            loading={submitting}
            onClick={handleSubmit}
            style={{ marginTop: 8 }}
          >
            发表评论
          </Button>
        </div>
      )}

      {/* 评论列表 */}
      <List
        loading={loading}
        dataSource={comments}
        renderItem={(item) => (
          <List.Item
            actions={
              item.canDelete
                ? [
                    <Popconfirm title="确定删除这条评论吗？" onConfirm={() => handleDelete(item.id)}>
                      <a>删除</a>
                    </Popconfirm>,
                  ]
                : []
            }
          >
            <List.Item.Meta
              title={
                <span>
                  {item.username}
                  <Rate disabled value={item.rating} style={{ fontSize: 12, marginLeft: 8 }} />
                </span>
              }
              description={item.content}
            />
            <div>{new Date(item.createTime).toLocaleString()}</div>
          </List.Item>
        )}
      />

      {/* 分页 */}
      <Pagination
        current={pageNum}
        pageSize={pageSize}
        total={total}
        onChange={setPageNum}
        style={{ marginTop: 16, textAlign: 'center' }}
      />
    </div>
  )
}
```

## 六、本课必须记住的 7 件事

1. **新增功能的标准流程**：需求分析 → 数据库设计（建表+索引）→ Entity → DTO/VO → Mapper（+XML）→ Service → Controller → 前端 API → 前端页面 → 测试
2. **数据库设计要点**：字段类型合理、必要的索引（高频查询字段+排序字段）、逻辑删除、时间戳自动填充
3. **后端分层**：Controller 接收请求+参数校验，Service 处理业务逻辑+权限校验，Mapper 数据访问，VO 给前端返回（包含关联表数据和前端需要的计算字段如 canDelete）
4. **多表查询用自定义 SQL**：评论需要关联用户名，在 Mapper 里写 LEFT JOIN，分页插件自动处理 COUNT 和 LIMIT
5. **权限校验在 Service 层**：删除评论时判断当前用户是否是作者或管理员，不能只靠前端隐藏按钮（前端可以绕过）
6. **前端组件化**：评论列表封装成独立组件 CommentList，通过 props 接收 bookId，在图书详情弹窗里引入
7. **测试要覆盖边界**：参数校验、权限校验、正常流程、异常流程都要测

### Q1：新增一个功能的完整开发流程是什么？

<details>
<summary>点击查看答案</summary>

   - Mapper（数据访问，单表用 BaseMapper，多表查询写 XML）

   - 页面/组件（UI + 交互 + 状态管理）

### Q2：评论表为什么要给 book_id 和 user_id 加索引？什么情况下用联合索引？

<details>
<summary>点击查看答案</summary>

**为什么加索引**：
- `book_id`：评论列表查询是 `WHERE book_id = ? ORDER BY create_time DESC`，这是高频查询（每次打开图书详情都查），不加索引会全表扫描，数据量大时很慢
- `user_id`：可能需要"我的评论"功能（`WHERE user_id = ?`），加索引
- `create_time`：排序字段，加索引避免 filesort

**什么情况下用联合索引**：
当查询条件包含多个字段，且这些字段经常一起查询时，用联合索引。比如评论查询是 `WHERE book_id = ? ORDER BY create_time DESC`，可以建联合索引 `idx_book_time(book_id, create_time)`：
- 先用 book_id 定位到这本书的所有评论（索引范围扫描）
- 这些记录在索引里已经按 create_time 排序了，不需要额外排序
- 这就是**覆盖索引**的思想，查询和排序都在索引里完成，不需要回表

联合索引遵循**最左前缀原则**：`idx(a, b, c)` 可以用于 `WHERE a=?`、`WHERE a=? AND b=?`、`WHERE a=? AND b=? AND c=?`，但不能用于 `WHERE b=?`（跳过了 a）。

项目里为了简单分开建了索引，生产项目建议用联合索引 `idx_book_time(book_id, create_time)` 替代单独的 `idx_book_id`。

</details>

### Q3：为什么删除评论的权限校验要在后端做？前端隐藏按钮不够吗？

<details>
<summary>点击查看答案</summary>

**前端隐藏按钮不够，必须在后端做权限校验**，原因：

1. **前端可以被绕过**：攻击者可以直接调用 API（用 Postman、curl 或修改前端代码），不通过页面按钮。前端隐藏按钮只是提升用户体验，不是安全措施。
2. **前后端分离架构**：后端 API 是公开的（只要知道 URL 和参数就能调用），必须在后端校验每个请求的权限。
3. **安全原则**：永远不要信任前端传来的数据，所有权限校验、业务校验都必须在后端做。前端校验只是为了减少无效请求和提升体验。

项目里的做法：
- 前端：`canDelete` 字段控制是否显示删除按钮（普通用户看不到按钮）
- 后端：`deleteComment` 方法里判断 `当前用户ID == 评论作者ID || 当前用户角色 == ADMIN`，不满足就抛 `NO_PERMISSION` 异常

即使普通用户绕过前端直接调用 `DELETE /api/comments/1`，后端也会返回"没有权限"，保证安全。

这是 Web 开发的基本原则：**前端校验是体验，后端校验是安全**。

</details>

### Q4：VO 和 Entity 有什么区别？为什么评论返回要用 VO 而不是 Entity？

<details>
<summary>点击查看答案</summary>

**区别**：
- **Entity（实体）**：对应数据库表，字段和表一一对应，用于数据访问层（Mapper/Service）。是"数据库视角"的对象。
- **VO（View Object / 视图对象）**：返回给前端的对象，字段根据前端需要设计，可以包含关联表数据、计算字段、格式化后的数据。是"前端视角"的对象。

**为什么评论返回用 VO 而不是 Entity**：

1. **包含关联表数据**：评论 Entity 只有 `user_id`，但前端需要显示用户名 `username`。VO 里加了 username 字段，从 sys_user 表关联查询出来。
2. **包含计算字段**：前端需要知道当前用户能不能删除这条评论，VO 里加了 `canDelete` 字段，后端根据当前用户和评论作者计算。如果用 Entity，前端需要自己判断（还需要知道当前用户ID和角色，不安全也不方便）。
3. **隐藏敏感字段**：Entity 里可能有 `deleted`、`update_time` 等前端不需要的字段，用 VO 可以只返回前端需要的字段，减少数据传输和信息泄露。
4. **解耦**：前端展示和数据库表结构解耦，表结构变化不影响前端（只要 VO 不变），VO 变化不影响数据库。

项目里的标准做法：Controller 返回 VO，不返回 Entity。Service 里把 Entity 转换成 VO（BeanUtils.copyProperties + 补充关联字段）。

这也是第7课讲的"三层对象（Entity/DTO/VO）"的实际应用。

</details>
