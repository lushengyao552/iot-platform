# 第1课：这个项目到底是怎么运行起来的？

> **本课目标**：建立"一个请求从浏览器到数据库再返回"的完整心智模型。不要求你懂每个注解的细节，只要求你能说清楚"数据是怎么流动的"。

---

## 一、一个真实请求的完整链路

以**"查询图书详情"**为例，当用户在前端点击某本图书时，整个过程是这样的：

```
用户点击图书
    │
    ▼
[前端 React] BookList.tsx 里调用 bookApi.getBookById(1)
    │
    ▼
[前端 Axios 封装] request.ts
    │  1. 从 localStorage 取出 Token
    │  2. 请求头加上 Authorization: Bearer <token>
    │  3. 发送 GET 请求到 http://localhost:8080/api/books/1
    │
    ▼
[HTTP 请求到达 Spring Boot]
    │  端口 8080，context-path 是 /api
    │  所以完整路径是 /api/books/1
    │
    ▼
[Spring MVC DispatcherServlet]
    │  收到请求，根据路径 /books/1 + GET 方法
    │  找到对应的 Controller 方法
    │
    ▼
[JwtInterceptor 拦截器]
    │  1. 检查请求头有没有 Authorization
    │  2. 验证 Token 是否有效、是否过期
    │  3. 解析出 userId、username、role
    │  4. 存入 UserContext（ThreadLocal）
    │  5. 放行，继续执行 Controller
    │
    ▼
[BookController.getBookById(1)]
    │  @GetMapping("/{id}")
    │  @PathVariable Long id  →  从 URL 路径中取出 id=1
    │  调用 bookService.getBookById(1)
    │
    ▼
[BookServiceImpl.getBookById(1)]
    │  1. 先查 Redis 缓存：key = "library:book:1"
    │     ├─ 缓存命中 → 直接返回，不查数据库
    │     └─ 缓存未命中 → 继续下一步
    │  2. 查数据库：bookMapper.selectById(1)
    │     （MyBatis-Plus 的 BaseMapper 提供的方法，自动生成 SELECT * FROM book WHERE id=1 AND deleted=0）
    │  3. 把 Book 实体转换成 BookVO（补充分类名称、是否可借）
    │  4. 写入 Redis 缓存，过期时间 30 分钟
    │  5. 返回 BookVO
    │
    ▼
[Controller 拿到 BookVO]
    │  包装成 Result.success(bookVO)
    │  返回 JSON：{ "code": 20000, "message": "操作成功", "data": {...}, "timestamp": ... }
    │
    ▼
[Spring MVC 把 Java 对象序列化成 JSON]
    │  Jackson 库负责，@RestController 注解自动做这件事
    │
    ▼
[HTTP 响应返回给前端]
    │
    ▼
[前端 Axios 响应拦截器]
    │  1. 判断 code === 20000 → 成功，把 data 提取出来
    │  2. 判断 code === 40100 → Token 过期，跳登录页
    │  3. 其他 code → 弹出错误提示
    │
    ▼
[React 组件拿到数据]
    │  setBook(bookData) → 更新组件状态
    │  React 自动重新渲染页面，显示图书详情
    │
    ▼
[请求结束]
    JwtInterceptor.afterCompletion() 被调用
    清除 UserContext 里的 ThreadLocal（防止内存泄漏）
```

**核心心智模型**：

> **前端发 HTTP 请求 → Spring Boot 接收 → 拦截器验证 → Controller 收参数 → Service 处理业务 → Mapper 查数据库 → 结果一层层返回 → 前端渲染页面**

## 二、项目启动时发生了什么？

当你运行 `LibraryApplication.main()` 方法时：

```java
@SpringBootApplication
@MapperScan("com.example.library.mapper")
public class LibraryApplication {
    public static void main(String[] args) {
        SpringApplication.run(LibraryApplication.class, args);
    }
}
```

### 背后发生的事情（简化版）

1. **`@SpringBootApplication` 生效**
   - 开启自动配置：根据 pom.xml 里的依赖，自动配置 Spring MVC、DataSource、Redis、RabbitMQ 等
   - 组件扫描：扫描 `com.example.library` 包下所有带 `@Component`、`@Service`、`@Controller`、`@Repository` 的类，创建对象放到 Spring 容器里
   - 配置类生效：`@Configuration` 标记的类（如 `RedisConfig`、`RabbitMQConfig`）被加载

2. **`@MapperScan("com.example.library.mapper")` 生效**
   - 扫描 mapper 包下的所有接口（如 `BookMapper`、`UserMapper`）
   - 为每个接口创建**代理对象**（你不需要写实现类，MyBatis-Plus 自动生成）
   - 把代理对象放到 Spring 容器里，Service 里可以直接注入

3. **启动内嵌 Tomcat**
   - 端口 8080（来自 application.yml）
   - context-path 设为 `/api`（所有接口路径前面都要加 /api）

4. **初始化连接池**
   - HikariCP 数据库连接池：连到 `localhost:3306/library_db`
   - Lettuce Redis 连接池：连到 `localhost:6379`
   - RabbitMQ 连接：连到 `localhost:5672`

5. **注册拦截器**
   - `WebMvcConfig` 里注册 `JwtInterceptor`
   - 白名单：`/auth/login`、`/auth/register`、`/auth/health` 不需要登录

6. **启动完成**
   - 打印 banner 和"图书管理系统启动成功！"
   - 开始监听 8080 端口，等待请求

## 三、项目里的 4 张表是什么关系？

```
┌──────────────┐       ┌──────────────┐       ┌──────────────┐
│   sys_user   │       │ borrow_record│       │     book     │
│   (用户表)    │       │  (借阅记录表)  │       │   (图书表)    │
├──────────────┤       ├──────────────┤       ├──────────────┤
│ id (PK)      │◄──┐   │ id (PK)      │   ┌──►│ id (PK)      │
│ username     │   │   │ user_id (FK) │───┘   │ isbn         │
│ password     │   └───│ book_id (FK) │       │ title        │
│ role         │       │ borrow_date  │       │ author       │
│ status       │       │ due_date     │       │ category_id  │
└──────────────┘       │ return_date  │       │ stock        │
                       │ status       │       └──────┬───────┘
                       │ fine         │              │
                       └──────────────┘              │
                                                       │
                                              ┌────────▼───────┐
                                              │ book_category  │
                                              │  (图书分类表)   │
                                              ├────────────────┤
                                              │ id (PK)        │
                                              │ name           │
                                              │ sort           │
                                              └────────────────┘
```

**关系说明**：
- **用户 1 : N 借阅记录**：一个用户可以借多本书
- **图书 1 : N 借阅记录**：一本书可以被多次借阅（不同时间）
- **分类 1 : N 图书**：一个分类下有多本图书
- 注意：项目里**没有建物理外键**（只有逻辑外键，通过 `category_id`、`user_id`、`book_id` 字段关联），这是企业项目的常见做法——外键约束放在应用层处理，不依赖数据库。

## 四、项目技术栈全景

| 层级 | 技术 | 项目里用在哪 |
|------|------|-------------|
| **Web 层** | Spring MVC + 内嵌 Tomcat | `spring-boot-starter-web`，所有 Controller |

| **工具库** | Hutool 5.8.27 | 字符串、日期、加密等工具方法 |

| **前端** | React 18 + TypeScript + Vite + Ant Design | `frontend/` 目录 |
| **部署** | Docker Compose | `docker-compose.yml`（MySQL + Redis + RabbitMQ） |

## 五、本课必须记住的 5 件事

1. **一个请求的完整链路**：前端 → HTTP → 拦截器 → Controller → Service → Mapper → MySQL，然后原路返回
2. **`@SpringBootApplication` 做了三件事**：自动配置 + 组件扫描 + 配置类生效
3. **`@MapperScan` 的作用**：扫描 Mapper 接口，自动生成代理对象，你不用写实现类
4. **项目的统一返回格式**：所有接口都返回 `Result<T>`，包含 `code`、`message`、`data`、`timestamp`
5. **4 张表的核心关系**：用户借图书，生成借阅记录；图书属于某个分类

## 六、自测题

### Q1：为什么前端请求的 URL 是 `http://localhost:8080/api/books/1`，而不是 `http://localhost:8080/books/1`？

<details>
<summary>点击查看答案</summary>

因为 `application.yml` 里配置了 `server.servlet.context-path: /api`。这意味着所有接口的路径前面都会自动加上 `/api` 前缀。Controller 里写的 `@RequestMapping("/books")` 实际对应的完整路径是 `/api/books`。

</details>

### Q2：`BookMapper` 是一个接口，没有实现类，为什么 `BookServiceImpl` 里能直接调用 `bookMapper.selectById(1)`？

<details>
<summary>点击查看答案</summary>

因为 `@MapperScan("com.example.library.mapper")` 扫描到 `BookMapper` 接口后，MyBatis-Plus 会在运行时为这个接口**动态生成代理对象**（用的是 JDK 动态代理）。这个代理对象实现了 `BaseMapper<Book>` 接口里的所有方法（selectById、insert、updateById 等），并把方法调用翻译成对应的 SQL。Spring 把这个代理对象放进容器，Service 里通过依赖注入拿到的就是这个代理对象。

</details>

### Q3：查询图书详情时，为什么要先查 Redis 再查 MySQL？直接查 MySQL 不行吗？

<details>
<summary>点击查看答案</summary>

可以直接查 MySQL，但用 Redis 缓存的目的是**减轻数据库压力、提高查询速度**。

- Redis 是内存数据库，读写速度比 MySQL（磁盘数据库）快 10-100 倍
- 图书详情是"读多写少"的数据，适合缓存
- 第一次查询时缓存未命中，查 MySQL 并写入缓存；后续 30 分钟内再查同一本书，直接从 Redis 返回，不碰数据库
- 这叫 **Cache Aside 模式**（旁路缓存），是最常用的缓存策略

但要注意：更新或删除图书时，必须清除对应的缓存（`evictBookCache` 方法），否则会出现缓存与数据库不一致的问题。

</details>

### Q4：`JwtInterceptor` 里的 `afterCompletion` 方法为什么要调用 `UserContext.clear()`？不清除会怎么样？

<details>
<summary>点击查看答案</summary>

`UserContext` 内部用的是 `ThreadLocal`。ThreadLocal 是线程级别的变量，每个线程有自己的一份副本。

Spring Boot 用的是 Tomcat 线程池，处理请求的线程是**复用**的——处理完请求 A 的线程，接下来可能处理请求 B。如果不清除 ThreadLocal 里的用户信息，那么：
1. 请求 A 的用户信息残留在线程里
2. 这个线程被分配给请求 B（可能是另一个用户，甚至是未登录的请求）
3. 请求 B 从 UserContext 里取到的是请求 A 的用户信息 → **数据错乱、安全漏洞**

另外，ThreadLocal 不清理还可能导致**内存泄漏**（线程池里的线程一直存活，ThreadLocal 里的对象一直被引用，无法被 GC 回收）。

所以 `afterCompletion` 里清理 ThreadLocal 是**必须的**，这是一种规范写法。

</details>

### Q5：为什么项目里的 `BookServiceImpl` 继承了 `ServiceImpl<BookMapper, Book>`？这个父类提供了什么？

<details>
<summary>点击查看答案</summary>

`ServiceImpl` 是 MyBatis-Plus 提供的 Service 层通用实现类。继承它之后，你的 Service 实现类**自动拥有了常用的 CRUD 方法**，不需要自己写：

- `getById(id)` — 根据 ID 查询
- `save(entity)` — 新增
- `updateById(entity)` — 根据 ID 更新
- `removeById(id)` — 根据 ID 删除（逻辑删除）
- `page(page, wrapper)` — 分页查询
- `count(wrapper)` — 统计数量
- `list(wrapper)` — 查询列表
- 等等...

`ServiceImpl<BookMapper, Book>` 里的两个泛型：
- 第一个 `BookMapper`：对应的 Mapper 接口
- 第二个 `Book`：对应的实体类

这样设计的好处是**减少重复代码**——每个 Service 都要写的基础 CRUD，MyBatis-Plus 帮你封装好了，你只需要写业务相关的自定义方法。

</details>

## 七、面试题

### 面试官问：请你说一下 Spring Boot 项目的启动流程，或者说一个 HTTP 请求从发起到响应的完整过程。

> **答题思路**（结合你的项目说）：
> 1. 启动时，`@SpringBootApplication` 触发自动配置和组件扫描，`@MapperScan` 扫描 Mapper 接口生成代理对象
> 2. 内嵌 Tomcat 启动在 8080 端口，初始化数据库连接池、Redis 连接、RabbitMQ 连接
> 3. 请求到达后，先经过 `JwtInterceptor` 拦截器验证 Token，白名单接口直接放行
> 4. `DispatcherServlet` 根据 URL 和 HTTP 方法找到对应的 Controller 方法
> 5. Controller 接收参数（`@PathVariable`、`@RequestBody` 等），调用 Service
> 6. Service 处理业务逻辑，可能查 Redis 缓存、调 Mapper 查 MySQL、发 MQ 消息
> 7. Mapper 通过 MyBatis-Plus 生成 SQL，操作 MySQL
> 8. 结果一层层返回，Controller 包装成 `Result` 对象
> 9. Jackson 把 Java 对象序列化成 JSON，通过 HTTP 响应返回前端
> 10. 前端 Axios 拦截器处理响应，React 更新页面渲染
> 11. 请求结束，拦截器的 `afterCompletion` 清理 ThreadLocal
