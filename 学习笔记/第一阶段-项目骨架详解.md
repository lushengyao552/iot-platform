## 一、阅读 pom.xml —— Maven 依赖管理

### 1.1 Maven 和 pom.xml 是什么

**Maven** 是 Java 的「项目构建 + 依赖管理」工具。核心思想：**你只管声明"我需要什么"，不用手动下载 jar 包、不用管 jar 之间的传递依赖和版本冲突**。所有声明写在 `pom.xml`（Project Object Model）里。

`pom.xml` 的关键是**坐标（GAV）**，全球唯一标识一个依赖：

```xml
<groupId>com.example</groupId>            <!-- 组织/公司域名反写 -->
<artifactId>library-management</artifactId> <!-- 项目/模块名 -->
<version>1.0.0</version>                   <!-- 版本号 -->
```

引入任何第三方库，本质就是告诉 Maven 它的 `groupId + artifactId + version`。

### 1.2 `<parent>` 继承机制

```xml
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.2.5</version>
    <relativePath/>
</parent>
```

继承 `spring-boot-starter-parent` 后，免费获得三样东西：

1. **版本统一管理（dependencyManagement）**：很多依赖（如 `spring-boot-starter-web`）没有写 `<version>`，版本全由父工程锁定，保证 Spring 相关组件版本互相兼容，避免版本冲突。
2. **默认插件配置**：`maven-compiler-plugin` 默认 Java 17 编译、`spring-boot-maven-plugin` 默认配好。
3. **默认资源编码**：统一 UTF-8。

> 这就是 Spring Boot「约定优于配置」在构建层面的体现。

### 1.3 `<properties>`：版本变量集中管理

```xml
<properties>
    <java.version>17</java.version>
    <mybatis-plus.version>3.5.5</mybatis-plus.version>
    <knife4j.version>4.4.0</knife4j.version>
    <jjwt.version>0.11.5</jjwt.version>
    <hutool.version>5.8.27</hutool.version>
</properties>
```

Spring Boot 官方管理的依赖不用写版本；但 Spring Boot **不管理**的第三方库（MyBatis-Plus、Knife4j、JJWT、Hutool）要自己声明版本。集中放在 `<properties>` 里，改版本只改一处。

### 1.4 `<dependencies>`：每个依赖的作用

#### 🧩 Spring Boot 官方 Starter 系列

| 依赖 | 作用 | 在本项目中的用途 |
|------|------|------------------|
| `spring-boot-starter-web` | Spring MVC + 内嵌 Tomcat + Jackson | HTTP 接口、内置服务器（8080）、JSON 序列化 |
| `spring-boot-starter-validation` | JSR-380 规范（Hibernate Validator） | 让 DTO 里的 `@NotBlank`、`@Size` 等校验注解生效 |
| `spring-boot-starter-aop` | 面向切面编程 | 拦截器、日志、权限等横切逻辑 |
| `spring-boot-starter-amqp` | RabbitMQ 客户端（AMQP） | 异步通知、延迟到期提醒、死信队列 |
| `spring-boot-starter-data-redis` | Redis 客户端（Lettuce） | 图书详情缓存、借阅分布式锁 |
| `spring-boot-starter-test` | JUnit5 + Mockito + Spring Test | 单元测试（`test` scope，不打包进生产） |

> **Starter 是什么？** 它不是一个"库"，而是"依赖打包器"。以前用 Spring 要引十几个 jar，现在一个 starter 全打包引入，即「起步依赖」思想。

#### 🗄️ 数据持久层

| 依赖 | 作用 |
|------|------|
| `mysql-connector-j`（`runtime`） | MySQL JDBC 驱动，运行时才需要 |
| `mybatis-plus-spring-boot3-starter` | MyBatis-Plus，`spring-boot3` 后缀是为 Spring Boot 3 适配 |

> ⚠️ MyBatis-Plus 有 `mybatis-plus-boot-starter`（Boot2）和 `mybatis-plus-spring-boot3-starter`（Boot3）两个版本。Spring Boot 3 使用 `jakarta.*` 命名空间（替代 `javax.*`），用错 starter 会启动报错。

#### 🔐 认证与安全（JJWT 拆成三个 jar）

| 依赖 | 说明 |
|------|------|
| `jjwt-api` | 核心 API（编译期需要） |
| `jjwt-impl` | 实现（`runtime`） |
| `jjwt-jackson` | JSON 序列化实现（`runtime`） |

> JJWT 拆分是**接口与实现分离**的设计：`api` 是代码里调用的接口，`impl`/`jackson` 是具体实现，`runtime` scope 表示编译时不需要实现类，运行时才加载。

#### 🛠️ 工具类

| 依赖 | 作用 |
|------|------|
| `hutool-all` | 国产工具库：字符串、日期、加密（BCrypt）、IO 等 |
| `lombok`（`optional=true`） | 编译期注解处理，自动生成 getter/setter/构造器 |

> `lombok` 标 `optional=true` 且打包时被 `<exclude>`，因为 Lombok 只在编译期生成代码，运行时不需要。

#### 📄 接口文档

| 依赖 | 作用 |
|------|------|
| `knife4j-openapi3-jakarta-spring-boot-starter` | Knife4j 4.4.0（Swagger 增强版），`jakarta` 后缀适配 Boot3，提供 `doc.html` 可视化调试界面 |

### 1.5 `<build>`：打包插件

```xml
<plugin>
    <artifactId>spring-boot-maven-plugin</artifactId>
    <configuration>
        <excludes>
            <exclude>org.projectlombok:lombok</exclude>
        </excludes>
    </configuration>
</plugin>
```

`spring-boot-maven-plugin` 把项目打成**可独立运行的 fat jar**（Tomcat 等依赖全打进去，`java -jar` 即可运行），并额外排除 Lombok。

## 二、阅读 application.yml —— Spring Boot 配置方式

### 2.1 为什么用 YAML 而不是 properties

Spring Boot 支持 `application.properties` 和 `application.yml` 两种格式。YAML 的优势是**层级缩进**表达更清晰，特别适合嵌套配置。二者本质等价，内部都会解析成 `key=value`。

> ⚠️ YAML 语法要点：**冒号后必须有空格**、**靠缩进（空格，不能用 Tab）表示层级**、同一层级缩进必须一致。这是新手最容易踩的坑。

### 2.2 逐段拆解

#### ① `server` —— 服务器配置

```yaml
server:
  port: 8080                    # 端口
  servlet:
    context-path: /api          # 全局前缀，所有接口都要 /api 开头
    encoding: {charset: UTF-8, enabled: true, force: true}  # 强制 UTF-8
```

- `context-path: /api` 解释了为什么接口文档地址是 `http://localhost:8080/api/doc.html`、为什么所有接口都是 `/api/xxx`。

#### ② `spring.datasource` —— 数据源（连接 MySQL）

```yaml
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://localhost:3306/library_db?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
    username: root
    password: ll521521          # 你自己的 MySQL 密码
    hikari: ...                 # HikariCP 连接池参数
```

- JDBC URL 结构：`jdbc:mysql://主机:端口/数据库名?参数`。
- URL 参数含义：`useUnicode/characterEncoding` 解决中文乱码、`useSSL=false` 关闭加密（本地开发）、`serverTimezone` 指定时区、`allowPublicKeyRetrieval` 允许 MySQL 8 密码认证。
- **HikariCP** 是 Spring Boot 默认内置的最快连接池，`maximum-pool-size: 10` 等参数控制连接复用。连接池意义：每次请求不用重新建立 TCP 连接。

#### ③ `spring.jackson` —— JSON 序列化

```yaml
jackson:
  date-format: yyyy-MM-dd HH:mm:ss
  time-zone: Asia/Shanghai              # 时区（否则差 8 小时）
  default-property-inclusion: non_null  # null 字段不返回给前端
```

- `non_null`：VO 里值为 null 的字段直接不返回，响应更干净。

#### ④ `spring.servlet.multipart` —— 文件上传（限制 10MB）

#### ⑤ `spring.rabbitmq` —— RabbitMQ 配置

```yaml
rabbitmq:
  host: localhost
  port: 5672              # AMQP 协议端口（不是 15672 管理界面）
  username: guest
  password: guest
  publisher-confirm-type: correlated   # 生产者确认消息是否到达交换机
  publisher-returns: true              # 无法路由时返回给生产者
  listener.simple:
    acknowledge-mode: manual           # 消费者手动 ack（防消息丢失）
    prefetch: 5                        # 预取数量（限流）
    retry: {enabled: true, max-attempts: 3, ...}  # 失败重试
```

- 这些是「消息可靠性」三板斧：**生产者确认 + 手动 ack + 重试**，属第三阶段深入内容，现在先知道它连了 RabbitMQ 即可。

#### ⑥ `spring.data.redis` —— Redis 配置

```yaml
data:
  redis:
    host: localhost
    port: 6379
    password:              # 留空表示无密码
    database: 0
    lettuce:
      pool: {max-active: 16, max-idle: 8, ...}  # Lettuce 连接池
```

- Spring Boot 3 默认用 **Lettuce** 客户端（替代旧的 Jedis），支持连接池。

#### ⑦ `mybatis-plus` —— ORM 框架配置

```yaml
mybatis-plus:
  mapper-locations: classpath:mapper/**/*.xml   # XML 映射文件位置
  type-aliases-package: com.example.library.entity  # 实体类别名
  configuration:
    map-underscore-to-camel-case: true  # 下划线转驼峰（snake→camel）
    log-impl: ...StdOutImpl              # SQL 打印到控制台（调试用）
  global-config:
    db-config:
      id-type: auto                      # 主键自增
      logic-delete-field: deleted        # 逻辑删除字段
      logic-delete-value: 1              # 已删除标记
      logic-not-delete-value: 0          # 未删除标记
```

- `map-underscore-to-camel-case` 极常用：数据库列 `create_time` 自动映射到实体属性 `createTime`。
- **逻辑删除**是重要概念：`deleted=1` 表示"已删除"，但数据还在库里。配合 schema.sql 每张表都有 `deleted` 字段，删除操作实际是 UPDATE 而非物理 DELETE，方便数据恢复和审计。

#### ⑧ `logging` —— 日志配置

- `level.com.example.library: DEBUG` 让你自己的代码输出 DEBUG 日志，`mapper: DEBUG` 能看到 SQL 细节。

#### ⑨ `library.*` —— 自定义业务配置（重点理解）

```yaml
library:
  jwt:
    secret: library-management-secret-key-...
    expiration: 86400000    # 24小时 = 24*60*60*1000 毫秒
    header: Authorization
    prefix: "Bearer "
  borrow:
    max-days: 30            # 最大借阅天数
    max-count: 5            # 每人最大借阅数
```

- 这是项目**自己定义的配置**，不是 Spring Boot 内置的。代码里用 `@Value("${library.jwt.secret}")` 或 `@ConfigurationProperties` 读取（对应 `JwtUtil.java`）。
- 学习价值：展示了**如何给项目加自定义配置项**，而不是只能用 Spring 官方的。

#### ⑩ `knife4j` + `springdoc` —— 接口文档配置

```yaml
knife4j:
  enable: true
  setting: {language: zh_cn, enable-search: true}  # 中文界面、搜索
springdoc:
  api-docs:
    path: /v3/api-docs          # OpenAPI 规范 JSON 端点
  group-configs:
    - packages-to-scan: com.example.library.controller  # 扫描哪个包生成文档
```

- Knife4j 4.x 底层基于 `springdoc-openapi`，扫描 Controller 里的 `@Operation` 等注解自动生成文档。

### 2.3 配置文件的核心机制

1. **外部化配置**：配置和代码分离，改配置不用改代码、不用重新编译。
2. **优先级**：命令行参数 > 环境变量 > `application.yml` > `application.properties`（后者覆盖前者）。所以生产常用环境变量注入密钥。
3. **自动绑定**：`spring.datasource.password` 这个 key 会被 `DataSourceProperties` 类自动读取并装配成 DataSource Bean——这就是"约定"的来源。

## 三、阅读 LibraryApplication.java —— 启动原理

```java
@SpringBootApplication
@MapperScan("com.example.library.mapper")
public class LibraryApplication {
    public static void main(String[] args) {
        SpringApplication.run(LibraryApplication.class, args);
    }
}
```

### 3.1 `@SpringBootApplication` —— 三个注解的"三合一"

| 组合注解 | 作用 |
|---------|------|
| `@Configuration` | 标记这是个**配置类**，类里可用 `@Bean` 定义组件 |
| `@EnableAutoConfiguration` | **开启自动配置**（Spring Boot 的灵魂） |
| `@ComponentScan` | 开启**组件扫描**，扫描启动类所在包及子包下的 `@Component`/`@Service`/`@Controller` 等注解并注册为 Bean |

> ⚠️ **包扫描范围**：`@ComponentScan` 默认扫描 `LibraryApplication` 所在包 `com.example.library` 及所有子包。所以 controller、service、mapper 都必须在 `com.example.library` 下才能被扫到。

### 3.2 `@MapperScan` —— 为什么需要它

MyBatis-Plus 的 Mapper 接口（如 `UserMapper extends BaseMapper<User>`）**没有实现类**，需要 MyBatis 用**动态代理**生成实现。`@MapperScan("com.example.library.mapper")` 就是告诉 MyBatis："扫描这个包下所有 Mapper 接口，给它们生成代理 Bean"。

> 对比：不写 `@MapperScan` 就得在每个 Mapper 接口上手动加 `@Mapper` 注解。集中式 `@MapperScan` 更省事。

### 3.3 `SpringApplication.run(...)` 启动流程

```
1. new SpringApplication()  —— 推断应用类型（Web 应用，因为有 Tomcat）
2. run() 内部：
   a. 创建 ApplicationContext（IOC 容器，默认 ServletWebServerApplicationContext）
   b. 加载自动配置类（从 META-INF/spring/xxx.AutoConfiguration.imports 读取）
      每个自动配置类用 @ConditionalOnClass/@ConditionalOnMissingBean 判断是否生效
      → 比如 classpath 有 DataSource 相关类，就自动配置 DataSource + HikariCP
   c. 组件扫描（@ComponentScan），把 @Service/@Controller/@Component 注册为 Bean
   d. 启动内嵌 Tomcat，监听 8080 端口
   e. 执行 CommandLineRunner 等回调
3. 返回就绪的上下文，应用进入"持续接收请求"状态
```

**核心理解一句话**：Spring Boot 不是"魔法"，它是**约定优于配置 + 自动配置**。引入 `spring-boot-starter-web`，它看到 classpath 有 Tomcat 类，就自动启动 Tomcat；配置了 `spring.datasource.*`，它看到这些属性，就自动装配 DataSource。几乎不需要写 XML 或 `@Bean`。

## 四、运行项目

### 4.1 运行需要哪些前置条件

从 `application.yml` 可知，应用启动要连 **3 个外部服务**：

1. MySQL（`localhost:3306`，数据库 `library_db`）
2. Redis（`localhost:6379`）
3. RabbitMQ（`localhost:5672`）

**当前环境**：Docker 已安装，通过 Docker Compose 可一键启动三个中间件。

### 4.2 推荐方案：用 Docker Compose 一键起中间件（最省事）

项目已提供 `docker-compose.yml`（配好 mysql:8.0、redis:7、rabbitmq:3.12，并自动执行 `schema.sql` 初始化数据）：

```powershell
# 第 1 步：启动 Docker Desktop（手动双击打开，等它就绪）
# 第 2 步：启动三个中间件
cd c:\Users\86150\Doubao\chats\2026-08-31\new-chat\library-management
docker-compose up -d

# 第 3 步：确认容器都健康（healthy）
docker ps
```

> ✅ 已核对 `docker-compose.yml`：`MYSQL_ROOT_PASSWORD: ll521521`，与 `application.yml` 里 `spring.datasource.password: ll521521` **完全一致**，无需改密码即可连接 Docker 中的 MySQL。只有当你的本地 MySQL 密码不是 `ll521521` 时，才需要修改 `application.yml`。

### 4.3 启动应用本体

```powershell
cd c:\Users\86150\Doubao\chats\2026-08-31\new-chat\library-management
.\mvnw.cmd spring-boot:run
```

- 首次会下载 Maven 和所有依赖（`target/` 目录已存在，说明之前编译过，可能有缓存会快很多）。
- 看到控制台输出 `图书管理系统启动成功！` 即成功。

### 4.4 通过 Knife4j 体验接口

启动成功后浏览器打开：

- **接口文档（Knife4j）**：http://localhost:8080/api/doc.html
- **健康检查**：http://localhost:8080/api/auth/health

体验顺序建议（这是理解业务的入口）：

1. **先登录**：在 Knife4j 找到「认证接口 → 登录」，用 `admin / admin123`（管理员）或 `user / user123`（普通用户）。
2. **拿到 Token**：登录响应里返回 JWT Token。
3. **点击 Knife4j 右上角「Authorize / 全局参数」**：把 Token 以 `Authorization: Bearer <token>` 形式填入（对应 `application.yml` 里 `header: Authorization` + `prefix: "Bearer "`）。
4. **逐个体验**：查询图书、借书、还书、查看分类……需要管理员权限的操作用 admin 账号试。
5. **观察现象**：借书后库存 `stock` 减 1，还书逾期产生 `fine` 罚款——第四阶段要深入讲的业务。
